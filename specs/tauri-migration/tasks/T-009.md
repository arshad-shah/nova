## Goal
A written report on whether the renderer's heavy views actually work on the
three OS WebViews (WebView2 / WKWebView / WebKitGTK) that replace v1's pinned
Chromium — ADR-0001 names this the compatibility risk surface, with WebKitGTK
the weakest link to test first. Findings feed T-101/T-105 config and, if a
view is broken, escalate before Phase 1 builds on sand.

## Acceptance criteria
- [ ] 1. Method documented and reproducible: the built renderer (or a
      storybook build exercising the target components) loaded in a minimal
      wry/Tauri shell per platform, at the wry version pinned in
      `versions.lock.md` (T-002). The report lists exact WebView engine
      versions per platform actually exercised; untested platforms are
      marked as such, never extrapolated.
- [ ] 2. **Monaco 0.55**: editor mounts, typing works, the completion popup
      renders, find widget opens, and web workers load (worker bootstrapping
      is the classic non-Chromium failure) — pass/fail per platform with
      screenshots in the spike dir.
- [ ] 3. **AG Grid 35**: a 100k-row grid scrolls without visual corruption
      and column resize/selection work — pass/fail per platform, with a
      subjective jank note (feeds the T-004/T-606 comparison, not a gate).
- [ ] 4. **@xyflow/react 12**: an ER-diagram-sized graph renders; pan/zoom
      and edge rendering work per platform.
- [ ] 5. **Platform seams inventoried for Phase 1**, each answered yes/no
      per platform: `navigator.clipboard` read/write availability (v1
      renderer relies on it — WebKit permission model differs), whether
      `-webkit-app-region: drag` CSS works or Tauri's
      `data-tauri-drag-region` is required (feeds T-105), keyboard shortcut
      interception differences (feeds T-106), and `import.meta.env.DEV` /
      Vite dev-server behavior under the WebView (feeds T-101).
- [ ] 6. Every failure has a severity call: blocker (escalate to human +
      ADR-0001 amendment), workaround (named, assigned to the Phase 1 task
      it lands in), or cosmetic. ADR-0001 is amended if any consequence
      changes.

## Notes
- Do not modify the renderer to make things pass — this spike observes; any
  needed shim is a finding assigned to a Phase 1 task.
- WKWebView needs macOS hardware; WebView2 needs Windows. Whatever this
  environment lacks gets the "not exercised" marking (criterion 1) and the
  Phase 1 gate's smoke matrix (T-199) carries the debt visibly.
- Monaco workers: under `tauri://` / custom protocols, worker URLs and CSP
  need explicit config — capture the exact working configuration in the
  report; T-101 copies it into `tauri.conf.json`.
