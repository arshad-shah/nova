## Goal
All 24 `ai:*` channels are served from Rust with v1 semantics — streaming
chat/explain with broadcast events, provider/model management with the
cheapest-model defaulting, key handling in the keyring, and the enhancement
endpoints — and the renderer's persisted-conversation flow works end-to-end
against the Rust conversation manager.

## Acceptance criteria
- [ ] 1. All 24 channels dispatched (burndown → migrated): chat:start/abort/
      approval-response; providers:list/list-configured/set-active/get-active;
      models:list/set-active/get-active; messages:list/clear/set; tools:list;
      keys:has/set; generate-sql; complete-sql; explain-results;
      explain:start/abort; conversation:summarize;
      permission:get-profile/set-profile.
- [ ] 2. `ai:chat:start` parity: returns `{streamId}` immediately; events
      stream via broadcast `ai:chat:event` with args `(streamId, event)`;
      loop errors broadcast as a terminal `{type:'error', error}` event;
      stream deregistered when finished. `ai:chat:abort` aborts the stream's
      controller AND the conversation manager. `ai:chat:approval-response`
      resolves T-504's pending approval.
- [ ] 3. Provider bootstrap parity (startup): legacy `ai.openaiKey`/
      `ai.anthropicKey` settings values migrated once into keyring ns
      `__ai__` then blanked in settings; saved `ai.activeProvider`/
      `ai.activeModel` restored; else anthropic-if-key, else openai-if-key;
      missing model defaults to `pick_cheapest_model` and persists the choice.
- [ ] 4. `ai:providers:list-configured`: anthropic/openai from keyring
      presence; Ollama probed via `GET <endpoint>/api/tags` with 2s timeout
      **after** the SSRF guard (`assert_safe_ollama_endpoint`) — unreachable
      or unsafe endpoint omits Ollama, never errors.
      `ai:providers:set-active` persists and re-defaults the model to the
      vendor's cheapest unless the current model belongs to the new provider.
- [ ] 5. Enhancements parity (enhancements.ts): generate-sql, complete-sql,
      explain-results (sync), conversation:summarize; and the explain stream —
      `ai:explain:start` returns `{streamId, model}` and broadcasts
      `ai:explain:event` payloads `{streamId, kind:'token', text}` /
      `{streamId, kind:'done', durationMs}` / `{streamId, kind:'error',
      message}`; `ai:explain:abort` cancels.
- [ ] 6. `ai:keys:has`/`ai:keys:set` operate on keyring ns `__ai__` only —
      an adversarial check greps config.json after key-set (secrets never in
      config, Phase-2 invariant). `ai:tools:list` returns
      `{id, name, description, permission}` projections.
- [ ] 7. Conversation persistence e2e: renderer flow (appdata conversations
      from T-205 + `ai:messages:set` on switch/branch) works against the Rust
      manager — scripted: persist a conversation, restart, switch to it, send
      a message, the request history contains the restored turns.
- [ ] 8. Contract fixtures: request/response pairs for all 24 channels
      captured from v1 round-trip byte-stably (per 04-ipc §type strategy);
      rejection-vs-return behavior per channel matches v1.
