## Goal
The v1 custom updater architecture ports as-is (ADR-0008 §2): a registry of
per-channel updaters where the first available channel wins, the Homebrew
channel shelling to `brew`, and the three `updater:*` channels with progress
streamed over `updater:progress`.

## Acceptance criteria
- [ ] 1. Registry parity: priority = registration order; `detect_active`
      returns the first updater whose `is_available()` is true; the result
      (including None) is **cached** for the process lifetime; a throwing
      updater is skipped, never blocks the rest; `invalidate()` clears the
      cache. Channel id enum preserved:
      `homebrew | mas | win-store | snap | apt | dmg-direct` (only homebrew
      implemented — planned ids stay ids, ADR-0008).
- [ ] 2. Homebrew availability parity — BOTH conditions required (a dev
      running an unmanaged build must never be offered a brew upgrade that
      would clobber it): platform is macOS or Linux, AND `brew --version`
      exits 0, AND `brew list --cask verql` exits 0.
- [ ] 3. Check parity: `brew outdated --cask --greedy --json=v2 verql`;
      non-zero exit → `{currentVersion, latestVersion: null,
      available: false}` (treated as no-update, never a thrown error); JSON
      parsed for `casks[].current_version` of the matching cask; `available`
      = latest non-null and ≠ current. Exact argv pinned by unit tests
      against a mocked command runner.
- [ ] 4. Update parity: emits progress `{phase:'downloading'}`, runs
      `brew upgrade --cask verql`; non-zero → `{phase:'error', message:
      stderr-trimmed or 'brew exited with code N'}`; success →
      `{phase:'done', restartRequired: true}` (brew replaces the bundle
      in-place; the running instance must restart).
- [ ] 5. `UpdateProgress` serialization matches v1 exactly (camelCase, the
      six phases idle/checking/downloading{percent?}/installing/
      done{restartRequired}/error{message}) — contract fixture.
- [ ] 6. Channels parity with src/main/ipc/updater.ts: `updater:status` →
      `{available:false}` or `{available:true, id, displayName,
      currentVersion}`; `updater:check` → `{supported:false}` or
      `{supported:true, currentVersion, latestVersion, available}`;
      `updater:update` → fire-and-forget `{started:true}` /
      `{started:false, reason:'no-updater'}` with progress (and any async
      failure as an error phase) broadcast on `updater:progress`.
- [ ] 7. Current version comes from the Tauri app version and equals the
      release version used by the cask templates (single source — assert in
      a test that tauri.conf.json/package.json versions agree, or document
      the single source chosen).
- [ ] 8. `tauri-plugin-updater` is NOT wired (ADR-0008: dmg-direct analog
      only if signing lands; not required for cutover) — a grep-check
      documents its absence.

## Notes
- Shell out with `std::process::Command` (02-target key mappings); capture
  stdout+stderr; never inherit a shell. Inject the runner for tests.
- v1 nuance: `detect_active` caching means a user who installs via brew
  mid-session isn't detected until restart — bug-for-bug, keep it.
- The cask name is `verql` (packaging/homebrew templates); T-602 owns the
  template updates — coordinate on the artifact naming they interpolate.
- Dispatch-table arms shared with other channel tasks; `src-tauri/Cargo.toml`
  gains one member line.
