## Goal
Every ADR moves from `proposed` to a status the human owner chose (`accepted`
or `amended` with the amendment text they approved). This is the migration's
first human touchpoint: the swarm does not dispatch Phase 1 against unratified
decisions, and ADR-0003's compatibility break (dropping the v1 JS plugin SDK
at launch) must be an explicit, quoted human decision — never an inferred one.

## Acceptance criteria
- [ ] 1. Each of the 8 ADRs was presented to the human owner individually:
      the decision in one paragraph, the alternatives rejected, and the
      consequences — not a bulk "approve all?" prompt. The presentation and
      the owner's response for each are recorded in this task's Log.
- [ ] 2. ADR-0003 sign-off is explicit and quoted verbatim in both this Log
      and an appended sign-off section in `ADR-0003-third-party-plugins.md`:
      the owner acknowledges that v2.0 drops JS plugin execution
      (`@verql/plugin-sdk` v0.11.0 has no v2 host), ships declarative
      plugins (themes, connection fields) only, and reports incompatible v1
      plugins by name at migration time.
- [ ] 3. Every ADR file's `Status:` line is updated to `accepted` (or
      `amended`, with the owner-approved amendment appended — never
      rewriting the original text), and the status table in
      `decisions/README.md` matches the files.
- [ ] 4. Any decision the owner changed (not just detailed) is escalated:
      the affected ADR gets the amendment, and the Log names which
      downstream tasks the orchestrator must re-scope before Phase 1.
- [ ] 5. If T-002's findings are available, they were surfaced during
      ratification (see Notes); if not, the owner was told which ADRs carry
      a `Verify-first: T-002` caveat (0001, 0004, 0006, 0008).
