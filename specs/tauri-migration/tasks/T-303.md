## Goal
The SQLite driver as a `verql-db` contribution crate on rusqlite: full
`SqliteAdapter` behavior parity, capabilities/connection fields serialized
identically to v1 — and the one sanctioned improvement: queries run on
`spawn_blocking` with `rusqlite::interrupt()`-based cancel and timeout,
fixing the documented v1 defect (docs/architecture.md "Known limitation —
SQLite runs synchronously on the main thread"; sanctioned in
01-current-state-inventory §known defects).

## Acceptance criteria
- [ ] 1. Connect parity: opens the file from the profile's `database` field,
      sets `journal_mode = WAL` + `foreign_keys = ON`; `test_connection`
      returns `{ version: <sqlite_version()> }`; `get_databases` returns
      `[<file basename>]`; `switch_database` errors with exactly
      `SQLite does not support switching databases`.
- [ ] 2. Query shaping ports `runPreparedStatement` including the
      reader-flag branch: statements that yield rows (SELECT, WITH…SELECT,
      returning PRAGMAs, and **INSERT/UPDATE/DELETE … RETURNING**) go down
      the rows path with fields from statement columns (declared type or
      `unknown`, `nullable: true`, `affectedRows: 0`); non-reader statements
      return `rows: [], fields: [], rowCount: 0` with `affectedRows` =
      changes. A RETURNING golden case pins this.
- [ ] 3. Sessions parity: in-memory session map on the single shared
      connection; implicit BEGIN when `autoCommit` off and not in txn;
      single-active-transaction exclusivity with the exact v1 message
      (`SQLite allows only one active transaction at a time; …`);
      `close_session`/`disconnect` roll back open txns; `set_auto_commit(true)`
      commits an open txn; unknown session id errors
      `No open session '<id>'`.
- [ ] 4. Sanctioned fix — non-blocking + cancel/timeout: all rusqlite work
      runs off the async runtime (`spawn_blocking`/dedicated thread);
      cancel/timeout use `Connection::get_interrupt_handle()` (ungated,
      `Send+Sync` — versions-baseline): `cancel_query` calls
      `InterruptHandle::interrupt()`; `timeout_ms` arms an interrupt
      watchdog on the same handle. Tests prove (a) a long query does not stall concurrent IPC
      (issue a slow query, assert another channel answers meanwhile),
      (b) cancel interrupts mid-query with `QUERY_CANCELLED` classification,
      (c) timeout interrupts with `TIMEOUT`. These assert the *corrected*
      behavior and are listed in the parity allowlist as sanctioned
      deviations (v1: blocking, no cancel, timeout unenforced).
- [ ] 5. Introspection parity against the seeded `docker/testdb.sqlite`:
      `get_tables` (sqlite_master, excludes `sqlite_%`, table|view, schema
      `main`), `get_columns` (PRAGMA table_info + foreign_key_list; empty
      type → `TEXT`; pk from `pk > 0`), `get_indexes` (index_list +
      index_info), `get_row_count`, `get_schemas` (PRAGMA database_list) —
      each pinned by goldens generated from v1.
- [ ] 6. Capabilities/registration identical to v1 `index.ts`: id `sqlite`,
      `sqlDialect: sqlite`, `quoteChar: "`, `placeholderStyle: positional`,
      `editorLanguage/statementSyntax: sql`, table/column/row nouns,
      `errorRules` = `sqliteErrorRules` verbatim, `defaultSchemaCandidates:
      ["main"]`, the single `database` file-path connection field (accept
      list included), `sampleQuery` (schema-qualified unless `main`),
      relational `getTableData`, explain `{ supportsAnalyze: false, format:
      text, statement: "EXPLAIN QUERY PLAN" }`, session block, and
      `generateMigrationDdl` with the INTEGER PRIMARY KEY rowid-alias
      special case. Serialized capability golden matches v1.
- [ ] 7. Type maps ported from `type-maps.ts` (pg→sqlite, mysql→sqlite,
      sqlite→mysql incl. fallbacks) and registered with T-310's registry.
- [ ] 8. Parity suite includes the 5 error cases — auth-fail analogue
      (unreadable/permission-denied file), unreachable (nonexistent path
      per v1 behavior: better-sqlite3 *creates* missing files — pin
      whichever v1 actually does), syntax error, constraint violation
      (UNIQUE), timeout (sanctioned-fix expectation) — asserting
      `DbErrorCode` classification via `errorRules` and message shape.
- [ ] 9. Type-fidelity goldens: INTEGER (incl. > 2^53 — pin v1's rendering),
      REAL, TEXT, BLOB (pin v1's wire serialization), NULL, boolean-ish
      0/1, and json-function output — field-for-field vs v1 goldens.

## Notes
- Bug-for-bug parity applies EXCEPT the sanctioned fixes in
  01-current-state-inventory §known defects — for this driver: the
  blocking/cancel/timeout trio (criterion 4). Everything else, including
  quirky messages, is preserved.
- Completions data (keyword/function lists in `index.ts`) belongs to the
  Phase-4 completion registry — port the data with the driver crate but
  registration may land behind a feature/stub until T-401.
- Coordination: registering the driver adds one line to the driver
  registration table (dispatch-table-adjacent, in `verql-ipc` boot or
  `main.rs` wiring) — a line shared with T-304..T-308; expect mechanical
  rebases. Workspace `members` line in `src-tauri/Cargo.toml` likewise.
- Goldens are generated only from v1 (`main`) by the T-005 generator; never
  hand-edit and never regenerate from this task.
