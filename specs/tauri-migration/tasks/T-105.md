## Goal
The Tauri window reproduces v1's shell (`src/main/index.ts`): renderer-owned
title bar on every platform — macOS `hiddenInset`-equivalent overlay with
repositioned traffic lights, Windows/Linux frameless with app-drawn controls
— plus the window-control channels and the `window:maximize-changed`
broadcast, so `TitleBar`/`WindowControls` behave identically under Tauri.

## Acceptance criteria
- [ ] 1. Per-platform decoration parity: macOS keeps native traffic lights
      overlaid on the renderer bar (title-bar-style overlay/transparent);
      Windows and Linux run `decorations: false` with the renderer's own
      min/max/close controls (v1 deliberately avoids Windows WCO — see the
      comment block in `src/main/index.ts`; do not reintroduce it).
- [ ] 2. Drag regions work: v1's `.drag-region` / `.no-drag` CSS
      (`-webkit-app-region`) does nothing under Tauri — apply
      `data-tauri-drag-region` per the T-009 findings such that: the title
      bar drags the window; `WindowControls`, `MenuBar` buttons, and tab
      strip remain clickable (Tauri's attribute does not cascade to
      children — verify the bar's *empty* areas drag, interactive children
      don't); double-click on the drag region toggles maximize on
      Win/Linux. Keep the Electron CSS intact for the v1 path (both shells
      run until cutover).
- [ ] 3. Dispatch arms implemented in `verql-ipc` window.rs (stubs →
      real), matching `src/main/ipc/window.ts` semantics exactly:
      `window:minimize` (void), `window:toggle-maximize` (**returns the
      new isMaximized bool**), `window:close`, `window:is-maximized`
      (bool), `window:set-titlebar-height` (macOS-only: recenter traffic
      lights at x=15, y=(height-12)/2 rounded, ignore non-finite/≤0; no-op
      elsewhere). All act on the **calling** window, not "focused".
- [ ] 4. `window:maximize-changed` (bool payload) is emitted via the T-102
      helper on every real state change — including OS-initiated ones
      (snap, double-click, unmaximize), mirroring v1's
      `maximize`/`unmaximize` listeners; the renderer's max/restore icon
      stays in sync without polling.
- [ ] 5. Burndown: the five channels above flip to `migrated`;
      `window:menu:list` / `window:menu:popup` stay `wontport`.
- [ ] 6. Renderer diffs are confined to the four listed files, and the
      Electron path still passes: `pnpm dev` shows the v1 shell unchanged;
      story tests for shell components stay green.

## Notes
- Traffic-light repositioning has no stable Tauri API — expect raw
  `objc2`/cocoa behind `#[cfg(target_os = "macos")]` (or a vetted plugin);
  whatever is chosen, the *behavior* contract is v1's: renderer reports
  real bar height (density-dependent) over `window:set-titlebar-height`,
  buttons recenter. If macOS hardware is unavailable, implement + unit-test
  the math, mark the manual check as debt for T-199's smoke matrix.
- `TitleBar.tsx` uses `env(titlebar-area-*)` (Windows WCO vars) — under
  Tauri frameless these resolve to the fallback values, which is correct;
  verify rather than rip out.
- Manual behavior verification (drag, snap, double-click) is scripted in
  T-199's checklist — this task's Log should record a first pass on the
  dev platform.
- `touches` intersects T-106 on `src-tauri/src/main.rs` — orchestrator
  serializes these two.
