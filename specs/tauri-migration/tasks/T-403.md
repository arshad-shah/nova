## Goal
`verql-themes` owns the theme model, token validation, and the core theme set
as data; `themes:list` and the `themes:changed` broadcast behave exactly as
v1, so the renderer's ThemeProvider/theme picker works unchanged and every
core theme renders pixel-identically.

## Acceptance criteria
- [ ] 1. `RegisteredTheme` model mirrors v1: `id`, `name`, `type` (dark|light),
      optional `tokens` map, optional raw `css` body, optional `monaco` def
      (`base` vs|vs-dark, `colors` map, `rules` [{token, foreground,
      background?, fontStyle?}]), optional `preview` {bg, sidebar, text,
      accent}, `source?`, `validation?` — serialized camelCase identical to
      v1's `SerializedTheme`.
- [ ] 2. `REQUIRED_THEME_TOKENS` (10 entries, from --color-bg-primary through
      --color-focus-ring) and `RECOMMENDED_THEME_TOKENS` (19 entries) are
      ported verbatim from sdk/theme-registry.ts — same tokens, same split.
- [ ] 3. `validate_theme` parity: collects declared vars from the `tokens` map
      (prefixing `--` when absent) AND from the css body via the
      `(--[a-zA-Z0-9_-]+)\s*:` pattern; `ok` ⇔ no missing required;
      recommended gaps are warnings. Pure function, unit-tested with the v1
      cases (tests/unit/theme-validation.test.ts ports).
- [ ] 4. Registry parity: duplicate id errors; registration runs validation
      eagerly and stores the report on the entry; `strict` option refuses
      registration listing the missing required tokens; change listeners fire
      on register/dispose and listener panics are isolated.
- [ ] 5. Every core theme in themes-data.ts ships as Rust-embedded data with
      **byte-identical** css bodies, monaco defs, and previews: nightshift,
      lab, inkpaper, dark, light, midnight, dracula, nord, solarized,
      catppuccin. Ion is deliberately absent (it ships with the renderer
      baseline, not a plugin — see themes-data.ts header comment).
- [ ] 6. `themes:list` returns the v1 response shape (contract fixture diffing
      a captured v1 response, field-for-field); `themes:changed` is emitted on
      any registry change (v1 wires registry.onChange → broadcast in
      ipc-handlers.ts:308).
- [ ] 7. Screenshot diff: the theme gallery story rendered under each core
      theme against the Tauri backend is pixel-identical to the v1 capture
      (same renderer — this verifies the theme *data* survived). Diffs
      attached to the task Log; any non-zero diff is a failure.
