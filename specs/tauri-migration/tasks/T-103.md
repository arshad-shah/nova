## Goal
The Rust side of the frozen contract is **checked, not trusted**: Rust mirror
types live in `verql-core::contract`, a CI drift check fails when either
`shared/*.ts` or the Rust mirrors change unilaterally, and a round-trip
fixture framework proves byte-stable deserialize→serialize for captured v1
payloads. This is what keeps ADR-0005's one untyped seam honest for the rest
of the migration.

## Acceptance criteria
- [ ] 1. The codegen/check mechanism is **evaluated and chosen** per 04
      §type strategy (`ts-rs` export from Rust vs schema extraction from
      TS), the choice + rejected option recorded in this Log. Whatever is
      chosen: TS remains authoritative; the check emits a machine-readable
      schema from each side and diffs them.
- [ ] 2. The drift check runs locally via one command
      (`node scripts/contract/check-drift.mjs`, exit 0/1 with a readable
      per-type diff) and in CI on `v2-tauri` (wired into
      `rust-ci.yml`). **Both directions demonstrated**: (a) add a field to
      a mirrored type in `shared/` only → check fails; (b) change the Rust
      mirror only → check fails; transcripts of both experiments in the Log
      (then reverted).
- [ ] 3. Mirror types follow the serde rules of 04: `rename_all =
      "camelCase"`, `skip_serializing_if = "Option::is_none"` where v1 omits
      keys (undefined vs null preserved), discriminated unions with
      `serde(tag = …)` matching v1 tag fields.
- [ ] 4. The channel list itself is drift-checked: the 143 wire strings +
      15 event strings in the T-102 dispatch table are compared against
      `shared/ipc.ts` extraction — retiring the count-only test as the
      sole guard.
- [ ] 5. Round-trip framework: fixtures under
      `tests/parity/fixtures/contract/<channel>/` hold request/response
      JSON (captured from v1 where feasible; hand-written marked as such);
      a Rust test walks all fixtures, deserializes into the channel's typed
      structs, re-serializes, and asserts byte-stable equality (after
      canonical JSON formatting — key order is not contract, presence/
      absence of keys is).
- [ ] 6. At least 3 channels covered as proof, chosen for type richness:
      `connections:save` (ConnectionProfile), `settings:set`
      (key-path + value + SettingsChangedPayload event shape), and one
      `appdata:*` channel (e.g. conversation shapes). Adding a fixture for
      a later channel must require zero framework changes (documented in
      `tests/parity/fixtures/contract/README.md`).
