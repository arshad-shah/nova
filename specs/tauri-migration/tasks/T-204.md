# T-204: `connections:*` (list/save/delete with secret handling)

- status: open
- phase: 2
- depends_on: [T-202, T-203]
- touches: [src-tauri/crates/verql-ipc/src/connections.rs]
- reads: [specs/tauri-migration/subsystems/config-store.md, src/main/ipc/connections.ts, src/main/ipc/secrets.ts, src/main/config/store.ts, shared/types.ts]
- risk: medium
- estimate: S
- verify.scope: rust, contract

## Goal
The three `connections:*` channels work over `verql-config` + `verql-keyring`
with v1's at-rest secret model intact: plaintext only in memory, blanked on
disk, `__SECRET_PRESENT__` on the wire to the renderer, real values merged
back in from the existing profile when the renderer echoes the placeholder.

## Acceptance criteria
- [ ] 1. `connections:list` returns every stored profile with each non-empty
      secret field replaced by `__SECRET_PRESENT__` (via
      `redact_connection` + the secret-field-key set from T-203's seam).
      Empty/absent secret fields are passed through untouched (v1 skips
      `undefined`/`''`/`null`).
- [ ] 2. `connections:save` runs the incoming profile through
      `merge_incoming_profile` against the existing stored profile (so a
      placeholder or blank secret keeps the previously saved value), persists
      via the store's save-with-secret-extraction path, and returns the saved
      profile redacted. A profile saved with a *new* password stores it in
      the keyring and blanks it on disk; saving the same profile again with
      the placeholder does not clobber the stored password (pinned by test).
- [ ] 3. `connections:delete` first disconnects and removes any active
      adapter for the profile (Phase-2 seam: the ConnectionManager doesn't
      exist until T-301 — call through an injected `ActiveConnections` trait
      whose Phase-2 impl is a no-op; T-301 provides the real one), then
      deletes all keyring entries for the profile, then removes it from the
      config store and saves. Order matters: keyring deletion is awaited
      before success is reported (v1 fix for fire-and-forget rejections).
- [ ] 4. Profile fields are passed through opaquely: `ConnectionProfile` is
      an open map plus known fields (drivers add arbitrary connection
      fields); serialization must not drop unknown keys
      (`#[serde(flatten)]`-style map, pinned by a fixture containing
      `sshHost`/`authSource`-like extras).
- [ ] 5. Contract fixtures: request/response pairs for all three channels
      round-trip byte-stably, including one profile with a secret
      (placeholder on the wire) and one without.
- [ ] 6. Adversarial case: after `connections:save` with a plaintext
      password, `config.json` on disk contains `""` for the field, the
      keyring contains the value, and the IPC response contains only the
      placeholder — asserted in one end-to-end test.

## Verify

cargo fmt --check

cargo test -p verql-ipc connections

## Notes
- The secret-field-key set in Phase 2 contains only `password` plus any
  fields registered through the T-203 seam; once T-301 lands, driver
  factories contribute their `type: 'password'` connection fields
  (`sshPassword`, `passphrase`, …). Design against the seam, not a constant.
- v1 `connections:list`/`save` are synchronous handlers; error shape on
  failure is a rejected promise with `message` — keep the thrown-error path,
  do not convert to a structured `{success}` result.
- Coordination: one dispatch-table line per channel in
  `src-tauri/crates/verql-ipc/src/dispatch.rs` (shared file). The
  `ActiveConnections` no-op seam (criterion 3) must be documented in code so
  T-301 replaces it rather than duplicating disconnect logic.
