## Goal
The engine core the six driver crates plug into: an async `Driver` trait
mirroring `DbAdapter` (all 12 required + 14 optional methods), a
`DriverRegistry` with factory metadata + serializable capabilities, a
thread-safe `ConnectionManager` replacing v1's `activeAdapters` map,
first-class cancellation and timeout plumbing, the `QueryResult`/schema
types, and the `DbErrorCode` mirror — no dialect logic anywhere in this
crate.

## Acceptance criteria
- [ ] 1. The `Driver` trait covers `db/adapter.ts` exactly: required
      `connect, disconnect, test_connection, query(sql, params, opts{
      session_id?, timeout_ms? }), get_tables, get_columns, get_indexes,
      get_row_count, get_schemas, get_databases, switch_database,
      is_connected`; optional (default-unimplemented, distinguishable from
      "failed") `set_schema, switch_warehouse, switch_role, cancel_query,
      get_connection_options, parse_query_plan, get_schema_objects,
      open_session, close_session, set_auto_commit, begin_transaction,
      commit, rollback`. Optionality is observable: glue must be able to
      no-op when a driver doesn't implement a method (v1 `adapter.foo?.()`
      semantics).
- [ ] 2. Driver *factories* carry the serializable capability set from
      `driver-capabilities.ts` (`sqlDialect`, `quoteChar`,
      `placeholderStyle`, `editorLanguage`, `statementSyntax`, `errorRules`,
      `nouns`, `session`, `explain`, `sessionInspection`,
      `defaultSchemaCandidates`, `defaultSchemaUseConnectionDatabase`,
      `connectionFields`, `hasSampleQuery`, `hasGetTableData`) plus the
      callable extras (`sample_query`, `get_table_data`,
      `generate_migration_ddl`, `get_runtime_capabilities`). Serialization
      matches `serializeStaticCapabilities` output field-for-field
      (camelCase, omitted-when-absent), pinned by fixtures.
- [ ] 3. `merge_capabilities` ports the overlay rules exactly: an overlay
      can only touch `session.{manualTransactions,isolationLevels,readOnly}`
      and `sessionInspection`, never enables a block the driver didn't
      declare, and never mutates the base.
- [ ] 4. `DbErrorCode` is mirrored as an enum with the exact 27 wire strings
      from `shared/db-errors.ts`; `DbErrorRule { code, pattern }` is
      data-only and serializes into capabilities.
- [ ] 5. `ConnectionManager`: per-profile adapter instances in a concurrent
      map (`DashMap`/actor); connect coalescing ports the v1
      `inFlightConnects` behavior (concurrent connects to one profile share
      one attempt; a failed attempt disconnects a partially-initialised
      adapter it didn't store); active-connection-id tracking with the
      "ignore stale ids for closed connections, null always allowed" rule;
      connection middleware hook points (`should_apply`/`before_connect`
      with a 15 s guard, `on_disconnect` errors logged but swallowed) for
      T-309.
- [ ] 6. Cancellation + timeouts are engine concepts: every running query
      registers a cancellation handle; `timeout_ms` is delivered to the
      driver and, for drivers that opt in, enforced by the engine's watchdog
      invoking the driver's cancel handle. No IPC handler can block the
      tokio runtime (blocking drivers declare it and get `spawn_blocking`).
- [ ] 7. `QueryResult { rows, fields, rowCount, duration, affectedRows }`,
      `FieldInfo`, `SchemaTable/Column/Index/Object`, `PlanNode`,
      `TestConnectionResult`, `SessionOpts` mirror `shared/types.ts` +
      `driver-capabilities.ts` with JS-number fidelity rules from 04-ipc
      (values that v1 stringified stay strings — per-driver golden cases pin
      this in T-303..T-308).
- [ ] 8. A `MockDriver` test double exercises the full engine surface
      (sessions, txns, cancel, timeout, middleware) without a real database;
      `cargo test -p verql-db` is green with no network/db dependency.
- [ ] 9. No engine- or dialect-specific branches anywhere in the crate
      (the `export-import-no-hardcoding` invariant extended to Rust —
      greppable: no `"postgres"`/`"mysql"`-style type literals outside
      tests).

## Notes
- v1 has no engine-level timeout watchdog — each adapter interprets
  `timeoutMs` itself (pg: statement_timeout; mysql: client option; sqlite/
  mongo/redis: ignored). Keep that dispatch shape: the engine passes
  `timeout_ms` through; the watchdog path exists for the sanctioned SQLite
  fix (T-303) only. Don't impose engine timeouts on drivers whose v1
  behavior ignored them.
- `implements`-style optionality must serialize into capability flags where
  v1 did (`hasSampleQuery`, `hasGetTableData`) — the renderer branches on
  those, not on driver type.
- Coordination: this crate's registry is where T-303..T-309 register — keep
  the registration API stable once the first driver lands, and expose the
  `SecretFieldSource` impl for T-203's seam (password-type connection
  fields). T-310 adds `type_map.rs` in this crate; leave room in `lib.rs`.
