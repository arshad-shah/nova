## Goal
The spec was written against a point-in-time snapshot of the ecosystem. This
task re-verifies every version/capability claim against **current** releases
and pins the result in `decisions/versions.lock.md` (a new appendix), amending
any ADR whose assumption drifted. After this task, no later task discovers
mid-port that a crate is dead or a Tauri capability doesn't exist.

## Acceptance criteria
- [ ] 1. `versions.lock.md` exists and pins, with the exact version checked
      and the date + source (crates.io / GitHub release) for each:
      Tauri 2.x current minor; the plugins `tauri-plugin-dialog`, `-opener`,
      `-notification`, `-os`, `-updater`, `-single-instance`,
      `-window-state`; `rmcp`; `keyring`; `russh`; `mysql_async`; `mongodb`;
      `redis`; `rusqlite`; `tokio-postgres`; the contract-check candidate
      (`ts-rs` or the alternative chosen); `wry`.
- [ ] 2. For each entry, a one-line maintenance verdict (active / slow /
      abandoned) with evidence (last release date, open-issue signal). Any
      "abandoned" verdict names a replacement candidate and amends ADR-0004.
- [ ] 3. Answered concretely, with citations, in the lock file:
      (a) does tauri-bundler currently produce MSIX, and if not what targets
      does it produce on Windows (feeds ADR-0008 + T-008);
      (b) does rmcp support the deprecated SSE transport, streamable-http,
      or both (feeds ADR-0006 — the requirement "existing SSE clients keep
      working" stands regardless);
      (c) `keyring` crate's Linux backend status (Secret Service /
      keyutils / headless behavior — feeds ADR-0007's fallback design);
      (d) wry's WebView engine + minimum version per OS (WebView2 /
      WKWebView / WebKitGTK) — feeds T-009's test matrix.
- [ ] 4. Every drifted ADR claim got an appended amendment (never a rewrite)
      referencing this task; unchanged ADRs are listed as re-verified in the
      Log.
- [ ] 5. Findings that change a *decision* (not a detail) are flagged for
      human ratification via T-001, named explicitly in the Log.
