## Goal
The PostgreSQL driver on tokio-postgres (ADR-0004): pooled connections,
`$n` placeholders, server-side `statement_timeout` on a dedicated
connection, pinned session clients with isolation levels, the EXPLAIN plan
parser (text + FORMAT JSON) producing v1-identical `PlanNode` trees, and
full parity against the seeded Postgres container.

## Acceptance criteria
- [ ] 1. Connection parity: pool of max 5, 30 s idle timeout; connect
      acquires-and-releases one client to validate; SSL verification is
      opt-out — certificates verified unless `sslMode == 'no-verify'`
      (`ssl` off ⇒ plaintext). Config fields map exactly as
      `postgres-adapter.ts` (host/port/database/username/password/ssl/
      sslMode).
- [ ] 2. Query parity: `$n` numbered placeholders (capability
      `placeholderStyle: numbered`); result shaping matches `shape()` —
      `fields[].dataType` is the **numeric type OID as a string**, `nullable:
      true`, `rowCount` = returned row count, `affectedRows` = command
      rowCount (0 for pure SELECT shape mismatch pinned by golden).
- [ ] 3. Timeout parity: `timeout_ms` acquires a dedicated client, runs
      `SET statement_timeout TO <floor(ms)>`, executes, and resets
      `statement_timeout TO DEFAULT` before releasing — even on error
      (a pooled connection must never leak a timeout). Timeout errors
      classify to `TIMEOUT` via `errorRules`.
- [ ] 4. Sessions/txns parity: `open_session` pins a client;
      queries on a session with autoCommit off implicitly BEGIN;
      `begin_transaction` validates isolation against exactly
      {READ COMMITTED, REPEATABLE READ, SERIALIZABLE} (error
      `Unsupported isolation level: <x>`), appends `READ ONLY` when asked;
      close/disconnect roll back open txns and release clients;
      `switch_database` serializes concurrent switches, rolls back and
      releases all sessions, ends and rebuilds the pool, and no-ops when
      already on the target database.
- [ ] 5. Plan parser ported from `plan-parse.ts` with output-identical
      trees for both the indented text format and `FORMAT JSON` (including
      the details-string assembly and Actual Total Time passthrough);
      goldens cover a nested join plan in both formats generated from v1.
- [ ] 6. Introspection parity (goldens vs seeded DB): `get_tables`
      (information_schema, default schema `public`), `get_columns`
      (columns + pg_index PK + FK triple-join), `get_indexes`
      (non-primary, ordered column arrays), `get_schemas` (excludes
      pg_catalog/information_schema/pg_toast), `get_databases`
      (non-template, allowed), `get_row_count` (schema-qualified quoted),
      and `get_schema_objects` — materialized views, functions vs
      procedures (prokind, signature/returnType shaping), non-internal
      triggers with parent, sequences, non-primary indexes with
      UNIQUE marker in `returnType`, and extensions only under `public`.
- [ ] 7. Capabilities/registration identical to v1 `index.ts`: quote `"`,
      nouns table/column/row, `errorRules` = `postgresErrorRules` verbatim,
      `defaultSchemaCandidates: ["public"]`, the 7 connection fields incl.
      the sslMode select options/defaults, sampleQuery, relational
      getTableData, explain `{ supportsAnalyze: true, format: tree,
      statement: "EXPLAIN ANALYZE" }`, session block with isolation levels +
      readOnly + rollbackKind full, generateMigrationDdl via the shared
      CREATE TABLE builder. Serialized capability golden matches v1.
- [ ] 8. Type maps (mysql→pg, sqlite→pg + fallbacks) ported and registered
      with T-310's registry.
- [ ] 9. Parity suite includes the 5 error cases — wrong password
      (AUTH_FAILED), unreachable host (CONNECTION_REFUSED), syntax error,
      constraint violation (unique + FK), statement timeout — asserting
      `DbErrorCode` classification and v1 message shape; plus type-fidelity
      goldens: int2/4/8 (bigint beyond 2^53 — pin v1's pg string
      rendering), numeric/decimal (string), bool, date/timestamp/timestamptz,
      bytea, json/jsonb, uuid, NULL, arrays.

## Notes
- Bug-for-bug parity; no sanctioned fixes for this driver. Notably v1 has
  **no `cancel_query`** on Postgres — `db:cancel-query` is a no-op; a
  tokio-postgres cancel token may back the *engine* watchdog only if it
  stays unobservable vs v1 (safer: don't add one; log the idea).
- `getRowCount` returns `parseInt` of pg's textual count — keep integer.
- pg returns `count(*)` and int8 columns as strings in JS; the OID-string
  `dataType` and stringified bigints are the two easiest parity misses.
- Coordination: one driver-registration line (shared with T-303..T-308) and
  the workspace `members` line in `src-tauri/Cargo.toml`.
- Goldens generated only from v1; never hand-edited, never regenerated here.
