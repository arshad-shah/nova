## Goal
The single seam of ADR-0005 exists: one Tauri command
`ipc_dispatch(channel, args) -> Result<Value, IpcError>` routing on the v1
wire strings, an event-emit helper for the 15 broadcast events, tracing
middleware around every call, and every one of the 143 invoke channels
registered — all as `NOT_MIGRATED` stubs. The match table doubles as the
migration's burndown metric from this task forward.

## Acceptance criteria
- [ ] 1. `verql-ipc` exposes `ipc_dispatch` registered in `main.rs`; unknown
      channels return a distinct error (`UNKNOWN_CHANNEL`) — never a silent
      None — so contract drift is loud.
- [ ] 2. The dispatch table contains **exactly** the 143 wire strings of
      `IPC_CHANNELS` in `shared/ipc.ts` (`db:query`, `settings:set`, …,
      counted from the source, not the docs). A unit test pins the count
      (143) and spot-pins at least one channel per domain (16 domains: db,
      ai, plugins, appdata, window, mcp, settings, connections, export,
      import, keyring, app, updater, activity, migration, dialog, themes).
- [ ] 3. Every handler returns the structured `NOT_MIGRATED` error: shape
      `IpcError { code: "NOT_MIGRATED", message }` with the channel named in
      the message — greppable, distinctive, and converted by the T-104 shim
      into a thrown renderer Error. `window:menu:list` and
      `window:menu:popup` are marked `wontport` in the table (permanent
      stubs, zero v1 renderer call sites — deleted at cutover per 04 §freeze).
- [ ] 4. Per-channel handler slots are typed functions in per-domain modules
      mirroring v1's `src/main/ipc/*.ts` one-to-one (window.rs, settings.rs,
      db.rs, …), so later tasks implement a channel by replacing one stub —
      each match arm names its owning task-phase in a comment.
- [ ] 5. Tracing middleware wraps every dispatch, replicating
      `src/main/ipc/context.ts`: records channel, duration, ok/err — and
      **never argument values** (secrets). The v1 exclusion set
      (`activity:list`, `activity:clear`, `activity:record`) is honored. In
      Phase 1 it emits `tracing` events; T-206 later re-points it at the
      activity stream (leave a named seam).
- [ ] 6. An emit helper sends broadcast events as
      `app_handle.emit(wire_string, payload)` covering exactly the 15
      `IPC_EVENTS` strings, pinned by a unit test; `menu:action` (T-106)
      and `window:maximize-changed` (T-105) will be its first callers.
- [ ] 7. `specs/tauri-migration/tasks/channel-burndown.md` is regenerated as
      the initial table: one row per invoke channel (143) + one per event
      (15), status `not_migrated` except the two `wontport` rows — emitted
      by a script/test from the dispatch table itself, not hand-typed, so
      the table cannot drift from the code.

## Notes
- **This task owns the dispatch match table.** Every later channel task
  (T-105/106/108, T-2xx…) edits only its own domain module's arms; the
  table structure, error types, tracing, and burndown generator stay here.
  Reshaping them later is an orchestrator-mediated change, not a drive-by.
- Extract the channel list from `shared/ipc.ts` mechanically (script or
  build step) rather than retyping 143 strings — T-103's drift check will
  formalize this; at minimum the unit-test count catches a miss.
- The `IpcError` serialized shape (message + optional code/details) is
  contract per 04 §error responses; T-104 depends on it — coordinate the
  exact field names via this task's Log before T-104 starts.
- Hot event channels (`ai:chat:event`, `activity:batch`) may later be
  backed by `tauri::ipc::Channel` per the ADR-0005 streaming addendum
  (events are documented as unfit for high-frequency streams) — the emit
  helper/dispatch plumbing must not preclude that; the mechanism is decided
  per-stream by T-206/T-503, not here.
- Touches `src-tauri/src/main.rs`, which T-105/T-106 also touch — the
  orchestrator serializes; dependency order mostly handles it.
