## Goal
`tests/parity/baseline-v1.md` records the v1 (Electron) numbers that Phase-3+
gates and T-606 compare against. Goal 4 ("footprint and performance win") is
"measured, not assumed" — this task is the measuring stick. Numbers are
produced by committed, re-runnable scripts, not one-off manual readings.

## Acceptance criteria
- [ ] 1. `tests/parity/baseline-v1.md` records, for v1 built from the commit
      hash it names: (a) cold start to interactive window (ms), (b) 100k-row
      query: execution → grid-rendered (ms) and peak RSS during it, (c) idle
      RSS after startup settles, (d) installer/bundle size for every
      platform actually built (name which; do not claim unmeasured
      platforms).
- [ ] 2. Each metric states its exact method: machine spec, OS, how the
      timestamps were taken (e.g. main-process start → renderer
      first-interactive mark), how RSS was sampled (which processes summed —
      Electron is multi-process; say so), and N runs with median reported
      (N ≥ 3 for timing metrics).
- [ ] 3. The 100k-row case runs against seeded test data (`scripts/test-dbs.sh
      up` / `docker/testdb.sqlite`) and the exact query is written down, so
      T-606 re-runs the identical scenario on v2.
- [ ] 4. Measurement scripts live in `scripts/perf-baseline/` and re-run
      cleanly; anything inherently manual (stopwatch-style observations) is
      explicitly marked manual with its procedure.
- [ ] 5. The file states its comparison contract: per
      `orchestration/verification.md`, regressions vs these numbers are
      gate failures from Phase 3 on unless an ADR accepts them.
