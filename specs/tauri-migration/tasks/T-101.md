## Goal
`src-tauri/` exists: a Cargo workspace matching the `02-target-architecture.md`
layout, a thin `main.rs` (builder, state, window setup), `tauri.conf.json`,
and a dev loop that boots the existing React renderer inside a Tauri window.
The renderer will be degraded (no bridge until T-104) — the bar is: the
window opens, the SPA loads, and the workspace passes the standing rust gate.

## Acceptance criteria
- [ ] 1. `src-tauri/Cargo.toml` is a workspace whose `members` use a
      `crates/*` glob, so later tasks add crates by adding a directory —
      never by editing this root manifest (it stays this task's exclusive
      turf; see Notes). Initial crates: `verql-core` and `verql-ipc`
      (skeletons: lib.rs, no logic — T-102/T-201 fill them).
- [ ] 2. Tauri + plugin versions match `decisions/versions.lock.md`;
      identifier is `com.arshadshah.verql` (ADR-0008 — NOT v1's
      `com.electron.verql`; the userData move is deliberate and handled by
      `verql-migrate-v1` later).
- [ ] 3. `main.rs` stays thin per 02: tauri::Builder, managed state
      placeholder, window creation. Window config mirrors v1
      (`src/main/index.ts`): title `Verql` (` — Dev` in dev builds),
      1400x900, min 800x600, background `#0d0d1a`. Default decorations for
      now — frameless/overlay is T-105's job; do not half-do it here.
- [ ] 4. `tauri.conf.json` points dev at the renderer dev server and prod at
      the renderer build output (reuse the existing electron-vite renderer
      build; document the URL/dist paths chosen). Monaco worker/CSP config
      from the T-009 report is applied if that report required it.
- [ ] 5. `pnpm dev:tauri` (script `scripts/dev-tauri.mjs` + `@tauri-apps/cli`
      pinned as a devDependency) starts the renderer dev server and
      `tauri dev`, and a window opens showing the SPA shell (degraded
      renderer state acceptable and expected — record a screenshot or
      description in the Log).
- [ ] 6. `cargo tauri build --debug --no-bundle` (or the pnpm equivalent)
      compiles and links on the dev platform.
- [ ] 7. `.gitignore` covers `src-tauri/target/` and generated artifacts;
      the standing rust gate passes on the new workspace; existing pnpm
      suites still pass (v1 untouched).

## Notes
- **Workspace-members coordination**: with the `crates/*` glob, T-102, T-103
  and every later crate task create directories without touching the root
  Cargo.toml — this is what keeps their `touches` disjoint. Workspace-level
  `[workspace.dependencies]` pins shared deps (serde, tokio, tauri) here.
- Do not register dialog/opener/notification plugins yet — each lands with
  the task that needs it (T-108 etc.); single-instance/window-state are
  post-Phase-1 niceties unless T-009 found a reason.
- `pnpm dev` (Electron) must keep working unchanged — the two dev loops
  coexist until cutover.
- Rust CI (T-003) automatically un-skips once this merges; watch the first
  real run.
