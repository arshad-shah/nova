## Goal
`verql-formats` provides every format implementation the v1 core-formats
plugin + SDK helpers + per-driver sql-format modules provided, registered into
the T-401 registries with the same ids/formats/`applies_to_types`, replacing
the Phase-3 stubs behind `export:*`/`import:*`. Deterministic exports are
byte-identical to v1 golden files.

## Acceptance criteria
- [ ] 1. Registered set matches v1: neutral `csv` + `json` exporters and
      `csv` importer (extensions csv,tsv) (core-formats); `jsonl` +
      `json-array` exporters and `jsonl` importer for mongodb-typed
      connections; `json` exporter for redis; per-dialect `sql`
      exporter/importer for postgresql (`applies_to_types:
      ["postgresql","postgres"]`), mysql, sqlite, snowflake — each
      `supports_schema: true`, importer `driver_executes: true`; display
      names preserved (e.g. "SQL (PostgreSQL)", "CSV / TSV").
- [ ] 2. CSV export byte parity with v1 golden files: zero rows →
      `columns.join(",") + "\n"`; null/undefined → empty cell; object values
      → JSON-encoded then CSV-quoted; other values stringified; quoting and
      record delimiter reproduce csv-stringify defaults (quote only when
      needed, `\n` records). Goldens generated from v1, never hand-edited.
- [ ] 3. JSON export = `JSON.stringify(rows, null, 2)` byte parity: 2-space
      indent, key **insertion order**, JS number formatting. Golden cases pin
      at least: nested objects, null, unicode, large/float numbers.
- [ ] 4. SQL export parity (per dialect quoteChar): `generateCreateTable`
      emission — two-space column indent, `PRIMARY KEY`, `NOT NULL` only on
      non-nullable non-PK, `DEFAULT <v>` passthrough, `;\n` tail;
      `formatSqlValue` — NULL, unquoted numbers, TRUE/FALSE, objects
      JSON-encoded with `'` doubled, strings with `'` doubled; empty rows emit
      `-- No data in <table>\n`; INSERT-per-row statement shape identical.
- [ ] 5. CSV import parity: header row → columns, `skip_empty_lines`, `trim`,
      delimiter parameter; and the generic csv→table path
      (`importCsvToTable`): one prepared INSERT built from `quote_char` +
      `placeholder_style` (numbered `$n` vs positional `?`), `on_conflict`
      semantics — `skip` counts skips, `error` and `update` both push
      `Row <n>: <msg>` into errors (v1 behavior for `update` is
      deliberate: surfaced, not silently dropped).
- [ ] 6. SQL importer parity: `splitSqlStatements` tokenizer port (single and
      double quotes, doubled-quote escapes, `--` and `/* */` comments,
      semicolon splits, trailing statement without `;`), executes per
      statement via the driver, collects `Statement <n>: <msg>` errors,
      reports `executed` count, returns no rows.
- [ ] 7. Formatters registered: dialect sql formatters (postgresql, mysql,
      sqlite, snowflake) with `applies_to_types`, generic `sql` fallback (no
      applies), mongodb `json` formatter, redis `plaintext`/`commands`
      formatter — and every formatter **returns the input unchanged on
      failure** (never destroys the buffer); unit test feeds garbage.
- [ ] 8. `export:formats-list` / `import:formats-list` now return the real
      registry contents in the v1 response shape (contract fixture), and an
      end-to-end export of a seeded table via `export:table` matches the v1
      golden byte-for-byte for csv and json.
