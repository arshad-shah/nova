## Goal
The MySQL driver on mysql_async: pooled connections (limit 5), backtick
identifier quoting, per-query timeout, `KILL QUERY`-based cancellation for
the engine's uniform cancel (ADR-0004), and full parity with the v1
`MysqlAdapter` against the seeded MySQL container — including its quirks
(no sessions, single-schema model).

## Acceptance criteria
- [ ] 1. Connection parity: pool limit 5, wait-for-connections semantics;
      config mapping host/port/database/username/password; `ssl` flag maps
      to TLS-on (v1 passes `{}` — default verification; pin observable
      behavior against the container). `test_connection` returns
      `{ version: <VERSION()> }`.
- [ ] 2. Query parity: positional `?` placeholders; result shaping — rows
      vs ResultSetHeader branch (`affectedRows` only for non-row results,
      `rowCount` = row count, rows empty for DML without rows);
      `fields[].dataType` is the **numeric mysql type code as a string**;
      `nullable` derived from the NOT_NULL flag handling both bitfield and
      flag-name-array shapes (port `isNullableFromMysqlFlags` incl. its
      documented precedence-bug history — the *fixed* behavior is v1
      current).
- [ ] 3. Per-query timeout: `timeout_ms > 0` bounds the query wait
      (v1: mysql2 `timeout` option). Timeout errors classify to `TIMEOUT`.
- [ ] 4. Cancellation: `cancel_query` issues `KILL QUERY <thread_id>` for
      the in-flight statement's connection (ADR-0004 mirror of mysql2
      semantics). Note: v1's adapter implements **no** `cancelQuery` —
      adding it realizes 02-target's uniform-cancellation design; record it
      in the parity allowlist as a designed deviation with a test asserting
      `QUERY_CANCELLED` classification.
- [ ] 5. No sessions/transactions — v1 parity: the adapter implements none
      of the session/txn methods, declares **no** `session` capability
      block, and the `db:session:*`/`db:txn:*` channels no-op or throw
      exactly as the T-302 glue dictates for a driver without them (pinned
      by a parity case).
- [ ] 6. Schema-model quirks preserved: `get_schemas` returns
      `[current database]` only (MySQL database == schema);
      `switch_database` runs `USE <quoted>` and updates the tracked current
      database; `get_databases` excludes mysql/information_schema/
      performance_schema/sys; introspection (tables/columns/indexes via
      information_schema with GROUP_CONCAT column ordering; PK from
      `column_key = 'PRI'`; FK map from key_column_usage) pinned by goldens
      vs the seeded DB.
- [ ] 7. Capabilities/registration identical to v1 `index.ts`: id `mysql`,
      `sqlDialect: mysql`, quoteChar backtick, `placeholderStyle:
      positional`, sql editor/statement syntax, table/column/row nouns,
      `errorRules` = `mysqlErrorRules` verbatim,
      `defaultSchemaUseConnectionDatabase: true`, the 6 connection fields
      with defaults (port 3306), sampleQuery, relational getTableData,
      explain `{ supportsAnalyze: true, format: text, statement: "EXPLAIN
      ANALYZE" }`, generateMigrationDdl via the shared builder — and **no
      session capability**. Serialized capability golden matches v1.
- [ ] 8. Parity suite includes the 5 error cases — wrong password
      (AUTH_FAILED), unreachable host, syntax error, constraint violation
      (duplicate key + FK), per-query timeout — asserting `DbErrorCode` via
      `errorRules` and message shape; plus type-fidelity goldens: TINYINT(1)
      /BOOL, BIGINT beyond 2^53 (pin v1 rendering), DECIMAL (string),
      DATE/DATETIME/TIMESTAMP (pin v1's JS Date→wire form), BLOB, JSON,
      ENUM, NULL.
- [ ] 9. Type maps from `type-maps.ts` registered with T-310's registry.

## Notes
- Bug-for-bug parity EXCEPT the KILL-cancel addition (criterion 4), which
  is a designed deviation per ADR-0004/02-target §concurrency — everything
  else, including the absent session support, is preserved. Do not "helpfully"
  add transactions.
- mysql2 date handling (JS `Date` objects serialized over IPC) is the
  subtlest fidelity surface — generate the golden from v1 and match its
  exact wire form rather than reasoning about it.
- Coordination: one driver-registration line (shared with T-303..T-308) and
  the workspace `members` line in `src-tauri/Cargo.toml`.
- Goldens generated only from v1; never hand-edited, never regenerated here.
