## Goal
Phase 2's exit criteria (03-migration-strategy §Phase 2 gate) are proven by
a verifier with full command transcripts, and the results are committed as
`gate-reports/phase-2-<date>.md`. Phase 3 does not open until this gate is
green.

## Acceptance criteria
- [ ] 1. Full standing gates pass over the whole workspace: `rust`
      (fmt/clippy/test), `renderer` (typecheck + unit project + affected
      stories), `contract` (regenerate bindings, zero diff, round-trip
      fixtures) — transcripts captured.
- [ ] 2. Channel coverage: every `settings:`, `appdata:`, `connections:`,
      `keyring:`, `activity:`, `dialog:`, and `app:` channel responds live
      (no `NOT_MIGRATED`); `channel-burndown.md` reflects the counts and is
      regenerated, not hand-edited.
- [ ] 3. Parity: the v1 `config.json` and `app.db` fixtures round-trip
      through the Rust stores (T-202/T-205 fixture suites, run from the
      gate, not taken on faith from task logs).
- [ ] 4. Adversarial secrets case: with a profile password saved via
      `connections:save`, a sweep of `config.json`, the activity stream
      (`activity:list` after exercising IPC), and captured tracing output
      finds no plaintext secret and no secret in any recorded argument.
- [ ] 5. End-to-end in the Tauri app (dev build): tab persistence
      (open/edit/restart/restore), query history (record + list + prune),
      and conversations (create/list/set-active/delete) all function against
      the Rust backend — scripted steps and observed results recorded in the
      report.
- [ ] 6. Smoke matrix: `cargo tauri dev`/`build` boots the app on the
      platforms available to the swarm; the report documents exactly which
      platforms were actually run (no claimed-but-unrun platforms).
- [ ] 7. `gate-reports/phase-2-<date>.md` committed with command
      transcripts, exit codes, and a pass/fail verdict per criterion above.
