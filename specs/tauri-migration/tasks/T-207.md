## Goal
The delivery-agnostic attention seam exists in `verql-core`: producers
(AI approvals, MCP approvals — Phase 5) announce "the user's response is
needed" without knowing how it is surfaced; consumers (os-notifications,
T-508) subscribe. A tiny, exact port of `attention-hub.ts`.

## Acceptance criteria
- [ ] 1. Types mirror v1: `AttentionKind` = `approval | alert | info`;
      `AttentionRequest { id, kind, title, body?, source? }`;
      `AttentionEvent` = `Requested(request) | Resolved { id }`.
- [ ] 2. `request()` marks the id pending and emits `Requested` to every
      subscriber; `resolve(id)` emits `Resolved` only if the id was actually
      pending — a double-resolve (timeout racing a user response) is a
      silent no-op (pinned by test).
- [ ] 3. `subscribe()` returns a disposable/guard that removes the listener;
      a panicking listener is caught and logged, never breaking the
      producer's `request`/`resolve` flow (v1 try/catch parity).
- [ ] 4. The hub is thread-safe (`Send + Sync`) and exposed through app
      state so both Phase-5 producers and the T-508 consumer reach the same
      instance; no IPC channels are added (the hub is internal — v1 exposed
      it only as the `attention` cross-plugin service).
- [ ] 5. No replay: a listener subscribing *after* a request was raised does
      not receive it (v1 has no pending-set replay — consumers that attach
      late simply miss earlier requests). Pin this; adding replay would
      change Phase-5 approval-flow timing observably.
- [ ] 6. Unit tests cover: request→resolve ordering, double-resolve no-op,
      resolve-without-request no-op, listener removal, panicking listener
      isolation, no-replay for late subscribers, concurrent request/resolve
      from two threads.

## Notes
- Deliberately tiny: no persistence, no delivery policy, no timeout logic —
  those belong to producers (Phase 5 approval flows own their 5-min
  timeouts) and consumers (os-notifications owns surfacing).
- v1 provided the hub to plugins under service id `attention`
  (`ATTENTION_SERVICE_ID`); keep the constant so Phase-4/5 service-registry
  wiring matches.
- Coordination: this adds one module to `verql-core` — a one-line `lib.rs`
  change shared with T-206's `activity/` addition; trivial rebase.
