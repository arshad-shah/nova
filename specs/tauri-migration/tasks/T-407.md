## Goal
All 22 `plugins:*` channels are served from Rust with v1 shapes, the
`plugins:lifecycle` and `plugins:ui:contributions-changed` events fire as in
v1, and a declarative third-party plugin (theme / connection fields) loads
end-to-end: install → validate → activate → contributions live → survives
restart → uninstall. Channels whose v1 meaning was tied to JS execution
return **honest, v1-shaped** empty results — never NOT_MIGRATED, never fake
success.

## Acceptance criteria
- [ ] 1. All 22 channels are dispatched (burndown rows flip to `migrated`):
      list, get-permissions, set-permissions, activate, deactivate,
      install-from-path, install-from-zip, open-install-dialog, uninstall,
      errors, get-settings, set-setting, get-categorized-settings,
      get-commands, connection-fields, middleware-fields, completions,
      drag-drop, ui:get-contributions, ui:resolve, ui:action,
      ui:contributions-changed.
- [ ] 2. `plugins:list` shape parity (contract fixture vs a captured v1
      response): bundled crates appear as plugins (`bundled: true`, status
      active, contributions from their live registrations), installed
      declarative plugins with real status, and IncompatibleJs entries with
      an error status naming ADR-0003; `requestedPermissions`/
      `grantedPermissions` from T-406; icon resolved to a data: URI from the
      plugin dir (never for bundled).
- [ ] 3. Contribution verification parity for declarative plugins: declared
      themes/connectionFields checked against what registered;
      partially-registered → `degraded` with `Missing contributions: …`;
      nothing registered → error `Plugin activated but registered no
      contributions. Expected: …`; theme entries with missing required tokens
      are demoted to missing + an error notification, missing recommended
      tokens warn (plugin-host.ts verifyContributions semantics).
- [ ] 4. activate/deactivate work for declarative plugins with persistence
      parity: user deactivation persists disabled state; boot skips disabled
      plugins (`inactive`); shutdown-path deactivation does NOT persist.
      Bundled crates: deactivation behavior decided and documented in this
      task's Log — parity default is v1's (deniable except essentials), but
      per ADR-0002 the essential/error-budget machinery does not apply to
      compiled-in code; whatever is chosen, `plugins:list` must reflect it
      truthfully.
- [ ] 5. Honest no-op table, pinned by fixtures, for JS-era channels:
      `plugins:errors` → `[]` (error budget gone per ADR-0002);
      `plugins:ui:resolve` → the v1 empty-resolution value;
      `plugins:ui:action` → error result (no plugin commands exist);
      `plugins:get-commands` → `[]`;
      `plugins:ui:get-contributions` → bundled contributions that still exist
      natively (e.g. toolbar/panel data served from crates) or `[]` per
      surface — each decision recorded in the burndown notes column.
- [ ] 6. Live-data channels parity: `connection-fields` from the driver
      registry factories; `middleware-fields` aggregates manifest
      connectionFields (ssh-tunnel fields must appear); `completions` routes
      to the native completion registry by driver→crate mapping;
      `get-settings`/`set-setting`/`get-categorized-settings` read/write
      `plugins.<name>.<key>` in the config store with schema defaults, and
      inactive/errored plugins' settings vanish from categories (v1 filter).
- [ ] 7. `plugins:open-install-dialog` uses tauri-plugin-dialog with v1
      filters (zip; file or directory selection), returns path or null.
- [ ] 8. Events: `plugins:lifecycle` `{name, event}` for
      activated/deactivated/installed/uninstalled at the same points as
      src/main/ipc/plugins.ts; `plugins:ui:contributions-changed` fires on UI
      registry change.
- [ ] 9. e2e (scripted, committed): a sample declarative theme+connectionFields
      plugin zip installs via `plugins:install-from-zip`, lifecycle event
      observed, its theme appears in `themes:list` and passes validation,
      state survives an app restart, uninstall removes it from disk and both
      lists.
