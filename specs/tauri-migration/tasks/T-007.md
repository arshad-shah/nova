## Goal
A written report proving (or refuting, before Phase 3 commits) that the
Snowflake SQL REST API v2 covers the v1 feature surface the `snowflake`
bundled plugin actually uses, and an ADR-0004 amendment recording what the
spike learned. T-308 implements from this report.

## Acceptance criteria
- [ ] 1. **Auth modes.** The report answers which of v1's three connection
      modes work against the REST API, with a demonstrated request each
      (live account or fully-cited docs where no account is available):
      password (`username`/`password`), key-pair JWT (v1: `privateKeyPath` +
      optional `passphrase` → `SNOWFLAKE_JWT`), and PAT. It explicitly
      addresses that v1's **default** authenticator is `externalbrowser`
      (SSO) — if the REST API cannot do browser-SSO, that is a parity gap
      that must be named, sized (which users hit it), and escalated to the
      human owner via the ADR amendment; never silently dropped.
- [ ] 2. **Query lifecycle.** How to submit a statement
      (`POST /api/v2/statements`), when responses are synchronous vs
      202+`statementHandle`, how to poll for completion, and how multi-
      partition results are fetched and stitched — with the shape of
      `resultSetMetaData`/`rowType` documented against what v1's adapter
      returns in `QueryResult` (column names/types, row value encoding —
      REST returns strings + type metadata; note the conversion burden).
- [ ] 3. **Introspection.** How each v1 adapter call maps: `SHOW WAREHOUSES`
      / `SHOW ROLES` (used by the toolbar resolvers, incl. the
      quoted-lowercase column-name quirk noted in `snowflake-adapter.ts`),
      `getTables`/`getColumns` via SHOW or INFORMATION_SCHEMA, and
      database/schema switching + `switchWarehouse`/`switchRole` (per-
      request `warehouse`/`role` fields vs session `USE` statements —
      which one preserves v1 semantics).
- [ ] 4. **Cancellation & timeout.** How to abort a running statement
      (`POST /api/v2/statements/{handle}/cancel`) and how a request-level
      timeout maps — enabling the sanctioned fix for the v1 defect
      "queryTimeout not enforced" (T-308 asserts corrected behavior).
- [ ] 5. **Rate limits & polling.** Documented request/rate limits and what
      they imply for the poll interval/backoff design; a recommended
      polling policy is stated.
- [ ] 6. ADR-0004's Snowflake row gets an appended amendment: confirmed /
      amended, the auth-mode matrix, and any parity gaps accepted by the
      human owner.

## Notes
- No seeded docker fixture exists for Snowflake; a live trial account is the
  realistic path — if none is obtainable, say so per criterion 1 and mark
  the affected answers documentary, not tested.
- v1 auth selection logic (`snowflake-adapter.ts` `connect()`): privateKey
  path present → `SNOWFLAKE_JWT`; else authenticator set and no password →
  passthrough (externalbrowser); else username/password. The report's
  matrix must cover exactly these three branches.
- PoC code (a minimal reqwest client) lives under the spike dir only.
