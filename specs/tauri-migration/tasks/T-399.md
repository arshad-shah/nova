## Goal
Phase 3's exit criteria (03-migration-strategy §Phase 3 gate) are proven
against the seeded test databases with full transcripts, committed as
`gate-reports/phase-3-<date>.md`. Phase 4 does not open until green.

## Acceptance criteria
- [ ] 1. Full standing gates over the workspace: `rust`, `renderer`,
      `contract` — transcripts captured after a clean rebase of `v2-tauri`.
- [ ] 2. Full driver parity suites green against the seeded DBs
      (`scripts/test-dbs.sh up` + the sqlite file) for sqlite, postgres,
      mysql, mongodb, redis — and snowflake against the live test account
      (documenting the account/creds source); every suite includes its
      5 error-parity cases and type-fidelity goldens. Runs executed by the
      gate, not inherited from task logs.
- [ ] 3. The SQLite defect fix is demonstrated: with a deliberately slow
      SQLite query running, (a) an unrelated IPC channel answers within
      normal latency (UI thread never blocks), (b) `db:cancel-query`
      interrupts it, (c) `timeoutMs` interrupts it — evidence (timings)
      in the report.
- [ ] 4. Per-query timeouts enforced on every driver that supports them,
      **including Snowflake** (the T-308 fix); non-enforcing drivers
      (mongo, redis) documented as v1-parity non-enforcement.
- [ ] 5. Channel coverage: all `db:` (31), `migration:` (2), `export:`/
      `import:` channels respond per their task contracts;
      `channel-burndown.md` regenerated — `import:csv`/`import:sql`
      stub-after-dialog status and any `db:format-query` stub recorded
      exactly as shipped.
- [ ] 6. Performance guardrails recorded vs `tests/parity/baseline-v1.md`
      (T-004): 100k-row query result execution→grid-rendered time and peak
      RSS, cold start to interactive — regressions vs v1 are gate failures
      absent an ADR exception (verification.md §performance guardrails).
- [ ] 7. SSH tunnel e2e (T-309's scenario incl. the sshd container) run and
      transcribed.
- [ ] 8. Smoke matrix: `cargo tauri dev`/`build` on the platforms actually
      available; the report lists exactly which ran.
- [ ] 9. `gate-reports/phase-3-<date>.md` committed with commands, exit
      codes, output excerpts, and a per-criterion verdict.

## Notes
- The verifier fixes nothing and commits nothing but the report
  (orchestrator commits it). Ambiguities in any driver task's verify block
  are reported as task-spec defects, not reinterpreted.
- Snowflake live runs may be constrained by account availability — if the
  live suite cannot run, the gate is NOT green; escalate to the human
  owner rather than passing on mocks (00-goals success criteria require
  all six drivers).
- Mid-phase partial runs of this gate (playbook §hygiene) are encouraged;
  only the full green run opens Phase 4.
