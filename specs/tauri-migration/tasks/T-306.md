## Goal
The MongoDB driver on the official Rust `mongodb` crate (3.x, tokio-only
since 3.0 — versions-baseline), porting the JSON
command-syntax translation layer (`statementSyntax: 'mongodb'`) — the
biggest non-SQL parity surface (ADR-0004) — plus result flattening and the
document-model capabilities, verified against the seeded Mongo container.

## Acceptance criteria
- [ ] 1. `parse_mongo_query` ports `parseMongoQuery` exactly: input is one
      JSON object; errors verbatim — `Invalid query: not valid JSON`,
      `Invalid query: must be a JSON object` (arrays rejected),
      `Invalid query: missing required field "collection"` / `"operation"`,
      and `Unknown operation: "<op>". Allowed operations: find, findOne,
      aggregate, count, distinct, insertOne, insertMany, updateOne,
      updateMany, deleteOne, deleteMany` (exact list, exact order).
- [ ] 2. The 11 operations execute with v1 semantics: `find` honors
      filter/sort/limit/projection in that application order; `findOne`
      wraps the doc in a 1-element array (empty when none); `aggregate`
      runs the pipeline; `count` → countDocuments scalar; `distinct`
      requires `field` (`distinct requires a "field" property`);
      `insertOne` → `{ insertedId }` (stringified), affectedRows 1;
      `insertMany` → `{ insertedCount }`; `updateOne/Many` →
      `{ matchedCount, modifiedCount }`, affectedRows = modifiedCount;
      `deleteOne/Many` → `{ deletedCount }`, affectedRows = deletedCount.
- [ ] 3. Result shaping ports `formatMongoResult`/`flattenDocument`: nested
      objects/arrays become **JSON strings** per top-level field; read
      results take field names/order from the *first* document only, all
      `dataType: unknown, nullable: true`; write results become a single
      row; scalars become `[{ result }]`; empty reads give
      `rows/fields: []`. ObjectId and BSON dates must flatten to the same
      strings v1 produced (goldens pin `_id` and date rendering — match the
      Node driver's JSON.stringify output, not Rust Debug).
- [ ] 4. Connection parity: URI built exactly as v1 `index.ts` —
      `mongodb`/`mongodb+srv` by `srv` flag, URL-encoded `user:pass@`,
      host:port omitted-port for srv, `/database`, `authSource` param only
      when username set (default `admin`), `tls=true` when `ssl`.
      `test_connection` returns `{ version: "MongoDB <serverInfo.version>" }`.
- [ ] 5. Introspection parity: `get_tables` lists collections (type `table`,
      schema = current database); `get_columns` samples ONE document and
      infers `dataType` from JS `typeof` semantics (object/string/number/
      boolean — match v1's strings), `_id` is the primary key, empty
      collection → `[]`; `get_indexes` from collection indexes (name,
      key-field names, unique default false); `get_row_count` =
      countDocuments; `get_schemas` = `[current database]`;
      `get_databases` via admin listDatabases; `switch_database` re-targets
      without reconnecting; `cancel_query` is a documented no-op (v1).
- [ ] 6. Capabilities/registration identical to v1: id `mongodb`,
      `editorLanguage: json`, `statementSyntax: mongodb`, nouns
      collection/field/document, **no** sqlDialect/quoteChar/
      placeholderStyle/errorRules/session/explain, sampleQuery returning
      the JSON `{"collection":…,"operation":"find","filter":{},"limit":100}`
      string, the plugin's own getTableData, and the 8 connection fields
      with defaults (port 27017, authSource `admin`, srv/ssl booleans).
      Serialized capability golden matches v1 (absent keys omitted).
- [ ] 7. Parity suite includes the 5 error cases with engine-appropriate
      analogues, each documented in the golden's allowlist: auth fail
      (bad credentials), unreachable host, "syntax error" = invalid JSON /
      unknown operation (criterion 1 messages), "constraint violation" =
      duplicate `_id` insert (E11000), timeout — v1 ignores `timeoutMs` for
      Mongo: pin that a long op is NOT cancelled (bug-for-bug; not on the
      sanctioned list).
- [ ] 8. Type-fidelity goldens: ObjectId, ISODate, embedded document,
      array, null, missing-field asymmetry across rows (columns come from
      doc #1), NumberLong/NumberDecimal renderings — field-for-field vs v1.

## Notes
- Bug-for-bug parity; no sanctioned fixes for this driver. The
  first-document-defines-columns behavior and the ignored `params`
  argument are quirks to preserve, not fix.
- The jsonl/json-array exporters and the AI context provider in the v1
  plugin belong to Phase 4/5 surfaces — port only the driver here; log the
  handoff.
- BSON→wire rendering is where Rust will naturally diverge (e.g.
  `{"$oid":…}` extended JSON vs v1's `ObjectId.toString()` inside
  JSON.stringify) — every such site must be forced to the v1 form; the
  goldens are the arbiter.
- Coordination: one driver-registration line (shared with T-303..T-308) and
  the workspace `members` line in `src-tauri/Cargo.toml`.
