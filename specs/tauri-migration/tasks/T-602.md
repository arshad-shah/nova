## Goal
tauri-bundler produces installable macOS artifacts (.app + .dmg, x64 and
arm64) under the new `com.arshadshah.verql` identifier, and the Homebrew tap
pipeline (`render-homebrew.mjs` + templates + bump workflow) is updated so
`brew upgrade --cask verql` keeps working across the v1→v2 transition.

## Acceptance criteria
- [ ] 1. `cargo tauri build` on macOS emits `.app` and `.dmg` for x64 and
      arm64 (universal or per-arch — decide, record in Log) with the app
      identifier `com.arshadshah.verql` (ADR-0008 — the userData move is why
      verql-migrate-v1 exists), product name Verql, and the brand icon from
      build/icon.* regenerated for Tauri's icon pipeline.
- [ ] 2. Signing posture matches v1 (ADR-0008 §3): unsigned dev-style builds
      (`identity: null` equivalent); no notarization gate is introduced;
      posture documented in the report.
- [ ] 3. Artifact naming compatibility: v1 casks interpolate lowercase
      electron-builder names (`verql-<version>-<arch>.dmg`). Either the
      bundler/CI renames Tauri artifacts to that exact scheme, or the
      templates change in the same commit — a rendered cask's URLs must
      resolve against the actual release asset names (asserted by test).
- [ ] 4. `scripts/render-homebrew.mjs` + `packaging/homebrew/*.tmpl` updated
      for the v2 artifacts: `render()`'s fail-closed placeholder semantics
      preserved (any unresolved `{{KEY}}` throws), tap files written whole
      (never in-place surgery), Casks/verql.rb + Formula/verql.rb both
      rendered; `tests/unit/render-homebrew.test.ts` updated and green.
- [ ] 5. `.github/workflows/homebrew-bump.yml` builds/bumps from the Tauri
      artifacts (sha256 per artifact: arm64 dmg, x64 dmg, AppImage —
      coordinate the AppImage sha with T-603).
- [ ] 6. Install proof: the .dmg mounts and the app launches on a real macOS
      machine; a locally-rendered cask passes `brew style` / `brew audit
      --cask` (or the failure is analyzed in the Log); T-601's updater
      detects the brew-managed install.
- [ ] 7. Artifact sizes recorded (dmg + .app, per arch) and handed to T-606's
      comparison (00-goals footprint win is measured, not asserted).

## Notes
- The identifier change moves userData — this is load-bearing for T-605's
  detection (v2 must NOT read/write the v1 Electron path). Do not "helpfully"
  reuse the old identifier.
- Version single-sourcing: package.json version drove v1 artifacts and
  release tagging (scripts/release-tag.mjs, changesets). Decide how
  tauri.conf.json version stays in lock-step (e.g. version field pointing at
  package.json or a sync check in CI) and record it.
- macOS runs must be documented honestly — if the swarm has no macOS host,
  this task blocks on the human owner for the install proof; say so in the
  Log rather than claiming an unexercised platform (verification.md).
- `src-tauri/tauri.conf.json` is shared with T-603/T-604 — these three
  packaging tasks serialize on it by design.
