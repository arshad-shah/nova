## Goal
The unified in-memory activity stream exists in `verql-core`: a ring-buffer
log with clipping, a batcher with v1's exact coalescing numbers, a
process-wide recorder sink, the three `activity:*` channels, and the
`activity:event` + `activity:batch` broadcasts — plus the per-IPC-call
tracing wired into the T-102 dispatch middleware with v1's secret
exclusions.

## Acceptance criteria
- [ ] 1. Log parity (`activity/log.ts`): ring buffer capped at 1000 entries
      (oldest dropped); `title`/`detail`/`stack` clipped to 2000 chars with a
      trailing `…`; `metadata` serialized-size-bounded to 8000 chars,
      over-size replaced by `{ _truncated: true, preview: <8000 chars>… }`,
      unserializable by `{ _unserializable: true }`; entries get a UUID `id`
      and epoch-ms `ts`; default level `info`; `list()` filters by
      kinds/levels/sinceTs, returns newest-first, applies `limit >= 0`; a
      panicking subscriber never breaks `record()`.
- [ ] 2. Batcher parity (`activity/batcher.ts`): flush when the buffer
      reaches **maxBatch = 50** entries, or **intervalMs = 100** ms after the
      *first* buffered entry (timer armed once, not per push); `flush_now`
      is a no-op when empty; `dispose` flushes remainder. These numbers are
      renderer-observable (its pause/resume logic depends on them) — pinned
      by unit tests with a mock clock.
- [ ] 3. Broadcasts: every recorded entry emits `activity:event(entry)`;
      batched delivery emits `activity:batch(entries)` oldest-first within
      the batch. Payloads serialize to `shared/activity.ts` shapes
      (camelCase, absent optionals omitted).
- [ ] 4. Recorder seam (`recorder.ts`): a process-wide `record_activity()`
      that is a no-op until the sink is installed at boot, so any crate can
      record without owning the log.
- [ ] 5. IPC tracing parity (`ipc/context.ts`): the dispatch middleware
      records one `kind: ipc` debug entry per successful call —
      title `"<channel> · <ms>ms"`, `source` = channel, `durationMs`,
      `metadata = { channel, args: <count> }` — and an error-level entry with
      `detail` = error message and `stack` on failure, then rethrows.
      **Argument values are never recorded** (they may carry secrets); only
      the arg count. Channels `activity:list`, `activity:clear`,
      `activity:record` are excluded from tracing (feedback-loop guard).
- [ ] 6. Channels: `activity:list(query)` → filtered entries;
      `activity:clear` empties the ring; `activity:record(entry-input)`
      appends a renderer-originated entry. Contract fixtures for all three
      round-trip.
- [ ] 7. A `traced_fetch`-equivalent helper (reqwest wrapper) exists in the
      activity module recording `kind: network` entries with method,
      host+path, status, duration — never bodies or auth headers — for
      Phase-5 AI/network consumers (port of `activity/net.ts`; unit-tested
      against a local mock server).
- [ ] 8. Fan-out uses bounded channels; when the consumer lags, entries are
      dropped per the batcher semantics rather than growing unbounded queues
      (02-target §concurrency).

## Notes
- The batcher numbers (100 ms / 50 entries) are load-bearing observable
  behavior per 04-ipc §event-stream parity — do not "improve" them.
- The tracing middleware itself lives in `verql-ipc/src/dispatch.rs`
  (T-102's file). This task supplies the sink + entry shapes and the
  exclusion set; if the middleware needs edits, coordinate — that file is
  the one every handler task adds lines to.
- v1's `metadata` size check measures the JSON string length, not entry
  count — replicate the measurement, not the intent.
- `activity:record`'s input is `RecordInput` (no id/ts) — the log assigns
  both; don't accept caller-supplied ids.
