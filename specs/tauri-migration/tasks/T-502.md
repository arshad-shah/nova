## Goal
The three AI providers exist as reqwest-based clients in `verql-ai` (no
vendor SDKs, matching v1's raw-fetch design), streaming SSE into the same
provider-chunk sequence v1 produced, with every request recorded into the
activity stream through a tracedFetch-equivalent.

## Acceptance criteria
- [ ] 1. Provider trait mirrors v1 `AIProvider`: id, name,
      supportsToolCalling, `models()`, streaming `chat(request)` yielding
      chunks `{type: text|tool-call|done|error, …}`; plus the provider
      registry (register/get/list/setActive/setActiveModel) and
      `pick_cheapest_model` (min costTier) ported.
- [ ] 2. Anthropic parity: `GET /v1/models` paginated (limit=100, after_id),
      headers `x-api-key` + `anthropic-version: 2023-06-01`; contextWindow
      and costTier heuristics ported (Opus/Sonnet ≥4.6 → 1M else 200k;
      haiku 0 / sonnet 1 / opus 2 / unknown 1). `POST /v1/messages`
      stream:true with: system message extracted from history; message
      conversion rules (assistant tool_use content blocks from parsed
      arguments; tool results as user `tool_result` blocks with consecutive
      results **merged into one user message**); `temperature` dropped for
      Claude 4.x per the two `supportsTemperature` regexes;
      `cache_control: {type:'ephemeral'}` on the system block and on the
      **last** tool only; max_tokens default 4096; stop_sequences pass-through.
- [ ] 3. Anthropic SSE parse parity: content_block_start/delta/stop handling,
      text_delta → text chunks, input_json_delta accumulated into the
      tool-call arguments string emitted **on content_block_stop**,
      message_start/message_delta usage accumulation, message_stop → done
      with `{inputTokens, outputTokens}`, error events surfaced; non-`data:`
      lines and unparseable JSON skipped.
- [ ] 4. OpenAI parity per providers/openai.ts: `GET /v1/models`,
      `POST /v1/chat/completions` streaming with delta tool-call assembly
      (index-keyed fragments concatenated into complete calls), model-name
      prettification + context-window table, cost-tier mapping — all as the
      v1 file implements them (read it; pin with fixtures).
      chat/completions is not deprecated and stays the multi-provider
      baseline; the Responses API is **out of scope** (versions-baseline).
- [ ] 5. Ollama parity: endpoint from `ai.ollamaEndpoint` (default
      `http://localhost:11434`); `assert_safe_ollama_endpoint` SSRF guard
      ported exactly (http/https only, no embedded credentials, blocked-host
      set + `169.254.*` link-local) and applied **before every request**;
      `GET /api/tags` for models with `POST /api/show` context_length
      enrichment (parallel fan-out, 8k fallback); `POST /api/chat` streaming.
- [ ] 6. Missing-key behavior parity: `models()` → `[]` without a key or on
      any HTTP/parse failure (never throws); `chat` errors with the provider's
      pinned message (e.g. 'Anthropic API key not configured'); non-OK chat
      responses error with `<Provider> API error <status>: <body>`.
- [ ] 7. Every request goes through a tracedFetch-equivalent that records a
      `network`-kind activity entry with the same fields v1's
      activity/net.ts records (method, url, status, duration) — verified by a
      test asserting entries appear in the activity log for a mocked call.
- [ ] 8. Fixture replay: raw SSE byte streams captured from v1 sessions
      (committed under tests/parity/fixtures/ai-sse/) parse into
      chunk sequences identical to the v1 parser's recorded output for all
      three providers, including a tool-call stream and an error stream.

## Notes
- HTTP: reqwest 0.13 (versions-baseline). SSE consumption via
  `eventsource-client` (LaunchDarkly, active) or reqwest `bytes_stream` +
  `eventsource-stream`; **not** `reqwest-eventsource` (stale since 2024).
- Anthropic gotchas (versions-baseline): newest models **400 on
  `temperature`/`top_p`/`top_k`** — check what v1 actually sends per
  request and record the handling in the parity allowlist (the v1
  `supportsTemperature` regexes may no longer cover every affected model);
  new stop reasons (`refusal`, `pause_turn`,
  `model_context_window_exceeded`) must not crash the parser — record
  their mapping in the allowlist too.
- API keys come from the keyring namespace `__ai__` (keys `openai`,
  `anthropic`) via T-203's crate — providers take a key getter, never read
  the keyring directly (v1 shape).
- The Ollama SSRF guard exists because the endpoint is a renderer-writable
  setting reaching a trusted-process fetch; do not weaken it, and apply it in
  `ai:providers:list-configured`'s probe too (T-505).
- Chunk *granularity* may differ from v1 (network reality); chunk **types,
  field shapes, and ordering** may not (04-ipc §event-stream parity).
- Coordination: T-503 consumes the provider trait; `src-tauri/Cargo.toml`
  gains the verql-ai member line (single-line conflict point).
