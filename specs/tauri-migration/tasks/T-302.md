## Goal
All 31 `db:*` channels route through `verql-db` with `ipc/db.ts` semantics —
connection lifecycle, query with activity recording, capabilities, sessions/
transactions, and the driver-owned extras (`sample-query`, `get-table-data`,
`parse-plan`, `format-query`) — with zero dialect knowledge in the handlers.

## Acceptance criteria
- [ ] 1. `db:connect` parity: already-connected short-circuits to
      `{ success: true }` and re-pins the active connection; concurrent
      connects share the in-flight attempt (T-301); middleware
      `before_connect` applies with the 15 s guard; success/failure returns
      the v1 `{ success: true } | { success: false, error }` shape (returned,
      not thrown) and records `kind: connection` activity entries with v1
      titles (`Connected to <name>` / `Connection to <name> failed`).
- [ ] 2. `db:disconnect` disconnects, drops the adapter, clears the active
      id if it matched, records activity, then runs every middleware
      `on_disconnect`, logging (not rethrowing) failures.
      `db:set-active-connection` ignores ids without an open adapter and
      always accepts null.
- [ ] 3. `db:query` calls the adapter with `(sql, params?, { sessionId?,
      timeoutMs? })`; on success records `kind: query, level: success` with
      title `"<rowCount> row(s) · <duration>ms"`, detail = the query text,
      source = connection *name*; on failure records detail
      `"<sql>\n\n<error message>"` and rethrows. The not-connected error
      message is exactly `Not connected — select a connection from the
      sidebar first`.
- [ ] 4. `db:test-connection` and `db:connection-options` build a throwaway
      adapter from the *merged* profile (incoming merged over stored via the
      secret rules — placeholder resolution) and always disconnect it in a
      finally; test-connection returns `{ success: true, ...result }` or
      `{ success: false, error }` (returned); connection-options returns
      `{}` when unimplemented and `[]` per field on per-field errors.
- [ ] 5. Introspection channels (`get-tables`, `get-columns`, `get-indexes`,
      `get-schemas`, `get-databases`, `get-row-count`, `get-schema-objects`
      → `[]` when unimplemented, `get-table-names` → mapped names) delegate
      verbatim. `db:get-table-data` and `db:sample-query` resolve through
      the *factory* (not the adapter) and fail with the v1 error messages
      when the driver doesn't contribute them (no orchestrator fallback —
      the DB-agnostic rule).
- [ ] 6. Context switches: `switch-database` rejects empty names
      (`Database name is required`); `set-schema`/`switch-warehouse`/
      `switch-role` no-op when the adapter lacks the method;
      `db:cancel-query` no-ops when no adapter or no `cancel_query`.
- [ ] 7. Session/txn channels (`session:open/close/set-autocommit`,
      `txn:begin/commit/rollback`) mirror v1's require-vs-lookup asymmetry:
      open/set-autocommit/begin *require* a connected adapter (throw);
      close/commit/rollback silently no-op when the adapter is gone.
- [ ] 8. `db:connection-capabilities` returns null unless both a runtime
      overlay provider and a live adapter exist; `db:driver-capabilities`
      serializes static capabilities or null for unknown types;
      `db:parse-plan` returns `[]` when no parser; `db:format-query`
      resolves a formatter by (language, connectionType) through the
      formatter seam (v1: `ipc-handlers.ts` line 188) — until Phase 4
      registers real formatters it returns the input unchanged or
      `NOT_MIGRATED` (pick one, record in Log, and keep the burndown table
      accurate).
- [ ] 9. Contract fixtures round-trip for all 31 channels (captured from v1
      where feasible), including the per-channel rejection-vs-return error
      parity (connect/test-connection return; query throws).

## Notes
- Use the T-301 `MockDriver` for handler tests; live-engine behavior is the
  driver tasks' parity suites, not this task's.
- The activity `source` for queries is the connection *display name*
  (falling back to the id) — an easy parity miss.
- `db:format-query` is the one `db:` channel not in `ipc/db.ts` (it lives in
  `ipc-handlers.ts`); don't forget it in the 31-channel count.
- Coordination: 31 dispatch-table lines in
  `src-tauri/crates/verql-ipc/src/dispatch.rs` (shared file — match arms
  only). Driver tasks (T-303..T-308) each add one registry-registration
  line elsewhere; nothing here should need editing when a driver lands.
