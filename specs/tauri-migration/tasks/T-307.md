## Goal
The Redis driver on redis-rs 1.x (crossed 1.0 in 2026; tokio +
`connection-manager` auto-reconnect — versions-baseline; the dormant
`fred` crate is not to be used): line-based
command execution with v1's parsing and result-table shaping, the
key-prefix pseudo-schema model, the command completions data, and full
parity against the seeded Redis container.

## Acceptance criteria
- [ ] 1. Command parsing ports `parseRedisCommands`: split on newlines,
      trim, drop empties, split each line on whitespace — no quoting
      support (v1 has none; a quoted string splits — preserve it).
      Commands are dispatched generically (the redis-rs equivalent of
      ioredis `call`), so unknown commands surface the server's `ERR`
      reply, never a client-side method lookup.
- [ ] 2. Result shaping ports `formatRedisResult`/`formatSingleValue`:
      nil → `[{ value: "(nil)" }]`; arrays → `{ index, value }` rows;
      object/hash replies → `{ field, value }` rows; scalars →
      `[{ value }]`. Multi-command input adds a `command` column (the
      joined original args) and inserts `{ command: "---", value: "---" }`
      delimiter rows between commands; field names come from the first
      row's keys. Goldens pin GET/nil, LRANGE, HGETALL, and a 3-command
      batch.
- [ ] 3. Connection parity ports `buildRedisConnection`: explicit field
      mapping only (host default `localhost`, port default 6379, optional
      username/password, `ssl` → TLS on, `database` number selected after
      connect when non-zero); connect PINGs to verify; `test_connection`
      parses `redis_version:` from INFO server →
      `{ version: "Redis <v>" }`; `is_connected` reflects a live/ready
      client; disconnect QUITs.
- [ ] 4. Pseudo-schema parity: `get_tables` = distinct first `:`-segment
      prefixes of `KEYS *` (whole key when no `:`), schema `db<N>`;
      `get_columns`/`get_indexes` return `[]`; `get_row_count(prefix)` =
      count of `KEYS <prefix>:*`; `get_schemas` = `["db<current>"]`;
      `get_databases` parses `db<N>` from INFO keyspace and always includes
      `db0` first; `switch_database("db<N>")` SELECTs (error
      `Invalid database: <x>` on non-numeric); `cancel_query` is a
      documented no-op (v1).
- [ ] 5. Capabilities/registration identical to v1 `index.ts`: id `redis`,
      `editorLanguage: plaintext`, `statementSyntax: redis`, nouns
      key/field/entry, **no** sqlDialect/quoteChar/placeholderStyle/
      errorRules/session/explain, sampleQuery = `KEYS <prefix>:*` with glob
      metacharacters in the prefix escaped (`*?[]\` → backslash-escaped),
      the plugin's own getTableData, and the 5 connection fields with
      defaults (port 6379, database 0). Serialized capability golden
      matches v1.
- [ ] 6. Completions data: the static `REDIS_COMMANDS` list ports with the
      crate (data-only) for the Phase-4 completion registry; registration
      may stub until T-401 (log the handoff).
- [ ] 7. Parity suite includes the 5 error cases with engine-appropriate
      analogues, documented per-case in the golden allowlist: auth fail
      (WRONGPASS/NOAUTH), unreachable host, "syntax" = unknown command ERR,
      "constraint" = WRONGTYPE (e.g. LPUSH then GET), timeout — v1 ignores
      `timeoutMs` for Redis: pin non-enforcement (bug-for-bug; not
      sanctioned).
- [ ] 8. Type-fidelity goldens: bulk string, integer reply, nil, array
      reply, hash reply, and a binary-unsafe value (pin v1's rendering) —
      field-for-field vs v1 goldens.

## Notes
- Bug-for-bug parity; no sanctioned fixes. The whitespace-only command
  splitting (no quote handling) and the `KEYS *`-based table listing
  (O(N) on large keyspaces) are v1 behavior — preserve, don't optimize;
  log improvement ideas instead.
- The multi-command `---` delimiter rows and the first-row-defines-fields
  rule are renderer-observable; goldens are the arbiter.
- The v1 plugin's json exporter ships in Phase 4 (`verql-formats`/T-402
  territory) — driver only here.
- Coordination: one driver-registration line (shared with T-303..T-308)
  and the workspace `members` line in `src-tauri/Cargo.toml`.
