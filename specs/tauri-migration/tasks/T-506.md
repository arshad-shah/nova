## Goal
`verql-mcp` serves the shared ToolRegistry to external MCP clients on
loopback over **Streamable HTTP at a single `/mcp` endpoint** per amended
ADR-0006 (rmcp 2.x; the legacy SSE transport is **not ported** — a
sanctioned wire-contract deviation, surfaced to users as a reconfiguration
notice), with v1's auth, gating, and status/activity surfaces intact; the
9 `mcp:*` channels manage it from the renderer with v1 shapes.

## Acceptance criteria
- [ ] 1. Transport per amended ADR-0006: rmcp 2.x `StreamableHttpService`
      (a tower `Service`) mounted via axum `nest_service` at `/mcp`
      (POST+GET, JSON-or-SSE responses, `MCP-Session-Id` /
      `MCP-Protocol-Version` per spec 2025-11-25), plus a plain `/health`
      route returning exactly v1's shape `{status:'ok', name:'verql-mcp'}`;
      anything else 404. **No legacy `/sse` + `/messages` endpoints** — a
      test asserts they 404.
- [ ] 2. Request pipeline: **`Origin` validation (spec MUST for local
      servers) → 403 on mismatch**, alongside v1's Host guard —
      `is_allowed_mcp_host` ported exactly (127.0.0.1 / localhost / ::1,
      port-suffix match, bracketed-IPv6 handling) → 403
      `{error:'Forbidden host'}`; then bearer auth → 401
      `{error:'Unauthorized'}` — guards before auth, auth before dispatch,
      on every request to `/mcp`.
- [ ] 3. Token parity: 32-byte hex bearer; **constant-time** comparison with
      explicit length guard; persisted in keyring ns `__mcp__` key `token`;
      generated when absent; legacy plaintext `mcp.token` in config.json
      migrated to keyring then scrubbed; `regenerate` mints + persists and a
      running server enforces the new token on the next request.
- [ ] 4. Port parity: `mcp.port` default 3100; `mcp.autoPort` default true
      probes 20 sequential ports on 127.0.0.1; `autoSelectedPort` flag
      reported; bind failure surfaces the v1 EADDRINUSE error shape.
      Binds 127.0.0.1 only — a test asserts no wildcard bind.
- [ ] 5. Tool gating parity (`select_exposed_tools`): excludes
      `mcp.disabledTools` ids, excludes write-permission tools when
      `mcp.readOnly`, excludes tools whose `surfaces` lacks 'mcp'
      (so `perform_app_action` is invisible); tool calls with no active
      connection return isError text
      `Error: No active database connection in Verql`; results serialize as
      `JSON.stringify(data, null, 2)`; execution routes through the
      **registry** (unified activity log records MCP calls like AI calls).
- [ ] 6. Activity parity: ring buffer capped at 100; entries `{id, timestamp,
      toolId, paramsSummary (≤120 chars with ellipsis), status
      ok|error|rejected, durationMs}`; each broadcast as `mcp:activity-event`.
- [ ] 7. The 9 `mcp:*` channels match src/main/ipc/mcp.ts: start (persists
      `mcp.enabled` true, returns `{port, token, autoSelectedPort}`), stop
      (persists false), status `{running, port, clients, token,
      autoSelectedPort}`, tools (all registry tools with enabled flags —
      including disabled ones), set-tool-enabled (updates
      `mcp.disabledTools`, reloads live server), activity, regenerate-token
      (returns status), reload (rebuild against current settings; no-op when
      stopped), approval-response (delegates to T-507) — v1 shapes, so the
      settings UI ports unchanged.
- [ ] 8. Client-reconfiguration notice (ADR-0006): the MCP settings UI
      surfaces a one-time notice that the endpoint changed, showing the new
      `http://127.0.0.1:<port>/mcp` URL + a copy-ready client config; the
      same notice feeds T-605's migration report.
- [ ] 9. Live-client e2e: Claude Code configured against the Rust server
      over Streamable HTTP (`claude mcp add --transport http
      http://127.0.0.1:<port>/mcp` with the Authorization header) connects,
      lists tools (gated set), and executes `list_tables` successfully
      against a seeded DB — transcript committed with the task.

## Notes
- rmcp had a breaking 2.0 (Jun 2026, aligned to spec 2025-11-25) and
  removed legacy SSE in v0.11.0 — pin `2.x` and treat it as replaceable;
  ADR-0006 sanctions hand-rolled JSON-RPC over axum if rmcp fights the
  approval-flow integration (the surface used is small: tools list/call +
  one transport).
- v1's `clients` count tracked SSE connections; under Streamable HTTP map
  it to live sessions (`MCP-Session-Id`) — decide multi-client behavior
  deliberately and record it; the `mcp:status` shape must not change.
- The timing-safe compare rationale (auth.ts) is part of the contract: a
  plain `==` is a rejectable security regression.
- Coordination: T-507 adds the approval path inside this crate; dispatch.rs
  arms shared with other channel tasks; `src-tauri/Cargo.toml` member line.
