## Goal
The Snowflake driver over the SQL REST API v2 with reqwest (ADR-0004 — no
official Rust driver; T-007's spike findings govern auth and API usage):
v1 adapter parity for query/introspection/context-switching plus the
sanctioned fix — the `queryTimeoutSec` plugin setting is actually applied
as `STATEMENT_TIMEOUT_IN_SECONDS` (v1 declares the setting but never
enforces it; 01-current-state-inventory §known defects).

## Acceptance criteria
- [ ] 1. Auth per ADR-0004 (amended) + T-007's recorded outcomes: **key-pair
      JWT (`privateKeyPath` + optional `passphrase`, key file read at
      connect) and PAT are first-class**; OAuth optional. SQL API v2
      accepts **no basic password auth** (versions-baseline; and MFA
      enforcement M3, Aug–Oct 2026, is ending password-only access
      generally) — password profiles and the unmappable `authenticator`
      modes (externalbrowser SSO, Okta URL) fail with a clear, actionable
      error naming the supported modes, per T-007's degradation matrix
      (cited in code and in this task's Log). Config mapping matches v1
      otherwise: `account` required; `database`/`schema`/`warehouse`/`role`
      sent only when provided; `host` overrides the account URL.
- [ ] 2. Number fidelity parity: v1 runs with `fetchAsString: ['Number']` —
      **every numeric column value arrives as a string**. The REST client
      must produce the same (REST returns strings natively; never parse
      them into f64/i64 for row values). Pinned by goldens covering NUMBER,
      DECIMAL, and large integers.
- [ ] 3. Result shaping: fields from result metadata (name, Snowflake type
      name matching v1 `col.getType()` strings, nullable);
      `affectedRows` = row count (v1 quirk — yes, even for SELECT);
      DML results (e.g. `number of rows inserted`) match v1's row shape.
- [ ] 4. Sanctioned fix — timeout: the driver applies the plugin setting
      `queryTimeoutSec` (default 120, from `settings.plugins` namespace) as
      the statement timeout on queries it issues (REST `timeout` /
      STATEMENT_TIMEOUT_IN_SECONDS per T-007), and `timeout_ms` from query
      opts takes precedence when set. A parity-allowlist entry records this
      as the corrected behavior (v1: setting declared, never read); a test
      asserts a long query fails with `TIMEOUT` classification at the
      configured bound.
- [ ] 5. Cancellation parity: `cancel_query` cancels exactly the in-flight
      statement (v1 tracks the active statement; REST: POST the cancel
      endpoint for that statement handle) — never a session-wide
      cancel-all. Concurrent introspection queries survive a cancel (v1
      comment is the spec).
- [ ] 6. Introspection + SHOW parity: `get_tables`/`get_columns` via
      INFORMATION_SCHEMA with default schema `PUBLIC`, PK/FK via
      `SHOW PRIMARY KEYS` / `SHOW IMPORTED KEYS` reading the
      quoted-lowercase column convention (`"column_name"`,
      `"fk_column_name"`, …); `get_indexes` returns `[]`;
      `get_databases` via `SHOW DATABASES` reading `"name"`;
      `get_connection_options` supports exactly warehouse/role/database/
      schema via SHOW (else `[]`); `get_row_count` via COUNT(*).
- [ ] 7. Context switching: `switch_database`/`set_schema`/
      `switch_warehouse`/`switch_role` issue quoted `USE DATABASE|SCHEMA|
      WAREHOUSE|ROLE` statements (or the REST session equivalent proven
      behavior-identical by parity cases — subsequent queries observe the
      new context).
- [ ] 8. Capabilities/registration identical to v1 `index.ts` — id
      `snowflake`, `sqlDialect: snowflake`, quote `"`, positional
      placeholders (`?` binds), sql editor/statement syntax, table/column/
      row nouns, `defaultSchemaCandidates: ["PUBLIC","public"]`,
      sampleQuery, relational getTableData, explain `{ supportsAnalyze:
      false, format: text, statement: "EXPLAIN" }`, generateMigrationDdl,
      **no** session capability — EXCEPT the connection-field set, which
      follows T-007's recommended set (account, key-pair fields, PAT; the
      `fetchable`/`step` metadata style preserved): a **sanctioned,
      product-visible deviation** from v1's password-first form (ADR-0004),
      pinned in the capability golden's per-case allowlist.
- [ ] 9. Parity suite includes the 5 error cases — auth fail, unreachable
      account/host, syntax error, constraint violation (NOT NULL / unique
      on a hybrid table, per what the seeded account supports — document
      the chosen case), timeout (criterion 4) — asserting classification +
      message shape; plus type-fidelity goldens: NUMBER-as-string, VARIANT
      /OBJECT/ARRAY, BOOLEAN, DATE/TIMESTAMP_NTZ/_LTZ/_TZ, BINARY, NULL.

## Notes
- Bug-for-bug parity EXCEPT the queryTimeout fix (criterion 4) and the
  auth/connection-field deviation (criteria 1+8; ADR-0004 + T-007
  outcome) — the only sanctioned deviations for this driver.
  `affectedRows = rows.length` is a v1 quirk to keep.
- `snowflake-connector-rs` 1.0 is the recorded fallback if owning the REST
  client stalls (ADR-0004; T-007's verdict says when to switch).
- Unit tests must run against a recorded/mocked REST server (goldens for
  request/response envelopes) so CI is green without credentials; live
  parity is gate-time.
- The v1 plugin's toolbar contribution (role/warehouse selectors), settings
  schema, and sql exporter/formatter are Phase-4 surfaces — port the driver
  +the `queryTimeoutSec`/`defaultRole`/`defaultWarehouse` setting *reads*
  here (settings live in `settings.plugins["verql-plugin-snowflake"]`);
  log the UI handoff.
- Owning REST means owning retry/session-expiry — bound scope to the v1
  feature surface actually used (ADR-0004 consequences).
- Coordination: one driver-registration line (shared with T-303..T-308) and
  the workspace `members` line in `src-tauri/Cargo.toml`.
