## Goal
The 00-goals footprint/performance win is demonstrated with numbers: v2 is
measured with T-004's exact methodology against the seeded databases and
compared metric-by-metric to `tests/parity/baseline-v1.md`. Any regression
versus v1 is a failure unless an ADR explicitly accepts it.

## Acceptance criteria
- [ ] 1. Same methodology as T-004 (its scripts under tests/parity/perf/
      reused, not rewritten): identical hardware/OS per compared pair,
      identical seeded data, N≥5 runs with median + spread reported —
      environment recorded (machine, OS, power state) so the comparison is
      honest.
- [ ] 2. Metrics measured on v2 (release build), per verification.md
      §performance guardrails:
      cold start → interactive window (ms);
      100k-row query: execution → grid-rendered (ms) AND peak RSS;
      idle RSS after settle;
      bundle/installer size per platform (dmg, AppImage, NSIS/MSIX — from
      T-602/603/604 artifacts).
- [ ] 3. `tests/parity/baseline-v2.md` committed with the same table
      structure as baseline-v1.md plus a delta column (absolute + %) per
      metric per platform measured.
- [ ] 4. Verdict per metric: improvement / parity / regression. Every
      regression is either (a) escalated and covered by an explicitly
      accepted ADR recording the trade-off, or (b) a blocking finding that
      freezes T-608 (deletion) until fixed — no silent acceptance.
- [ ] 5. The known v1 defect fix is re-demonstrated at the perf level: a
      long-running SQLite query leaves the UI interactive and cancellable in
      v2 (the v1 baseline records the freeze) — included as a narrative
      section with measurements.
- [ ] 6. Platforms not measured are listed as not-measured (with reason),
      never extrapolated; at minimum the primary dev platform is fully
      measured and the gaps are called out for the cutover checklist.
- [ ] 7. Numbers feed the phase-6/final gate report (T-699) unchanged —
      the gate re-runs spot checks; discrepancies beyond run-to-run noise
      are findings.

## Notes
- baseline-v1.md is regenerated only from v1 `main` (T-004); if v1 numbers
  look stale relative to the final v1 release, request a re-baseline from the
  orchestrator — never edit the baseline to make a comparison pass.
- Measure release builds only (`cargo tauri build` output); dev builds
  measure the toolchain, not the product.
- RSS on three OSes means three different definitions — use the same probe
  T-004 used per platform and name it in the report.
- Coordination: artifact sizes come from T-602/603/604's outputs; this task
  does not rebuild packages, it records theirs.
