## Goal
`src/renderer/src/lib/backend-bridge.ts` is the only renderer module that
knows which shell hosts the app. It exposes the `BackendBridge` interface of
04 (`platform`, `invoke`, `on`) with an Electron impl (delegates to the
preload bridge) and a Tauri impl (`ipc_dispatch` + `listen`), and assigns the
result to `window.electronAPI` — so all 166 existing call sites, the
Storybook stub, and the 12 unit-test stubs keep working **unmodified**.

## Acceptance criteria
- [ ] 1. The bridge implements exactly the preload shape
      (`src/preload/index.ts`): `platform`, typed
      `invoke(channel, ...args)`, `on(channel, cb) → unsubscribe`. Nothing
      more — new surface area is contract creep.
- [ ] 2. Selection is feature-detection (`'__TAURI_INTERNALS__' in window`),
      no build flag. Under Electron the preload has already set
      `window.electronAPI`; the shim must detect it and leave it untouched.
      Likewise it must never clobber a pre-existing stub — the Storybook
      stub (`.storybook/preview.tsx`) and unit tests assign their own
      `electronAPI` first, and they run with neither Electron nor Tauri
      present (falls through to a `platform: 'web'` no-backend state, not a
      crash).
- [ ] 3. Tauri `invoke` calls `ipc_dispatch` with `{ channel, args }` using
      the `IPC_CHANNELS` constants (the string-literal-channel CI test,
      `tests/unit/audit/ipc-channels-single-sourced.test.ts`, stays green);
      `on` maps to Tauri `listen` spreading `e.payload` into the callback
      args and returning an unsubscribe function.
- [ ] 4. Error parity per 04: an `IpcError { message, code?, details? }`
      rejection from Rust (field names as fixed in T-102's Log) surfaces as
      a thrown `Error` whose `.message` matches — `NOT_MIGRATED` errors
      included, so unported channels fail soft and greppably.
- [ ] 5. `platform` is hydrated **before first render**: `main.tsx` awaits
      the OS-plugin resolution (mapped to `'darwin' | 'win32' | 'linux'`)
      before `createRoot(...).render(...)` under Tauri, so
      `lib/platform.ts` (which reads `window.electronAPI.platform`
      synchronously at import) never sees a wrong value — no
      flash-of-wrong-platform title bar. `lib/platform.ts` itself is NOT
      modified.
- [ ] 6. These pass unchanged (spot list of the 12 stub files):
      `tests/unit/stores/connections-active-sync.test.ts`,
      `tests/unit/ipc-channels-coverage.test.ts`,
      `tests/unit/ai-store.test.ts`,
      `tests/unit/components/connections/ConnectionFormView.test.tsx`, and
      `.storybook/preview.tsx`-based story tests — zero diffs under
      `tests/` and `.storybook/`.
- [ ] 7. Under `pnpm dev` (Electron) the app behaves exactly as before —
      the shim is inert when the preload bridge exists.

## Notes
- `main.tsx` import order matters: `lib/platform.ts` computes at module
  scope, so the hydration must happen before any module that imports it is
  evaluated — a tiny pre-entry (dynamic `import()` of the real app after
  hydration) is the known-good pattern; document what you do.
- `@tauri-apps/api` joins package.json (T-101 already added the CLI); keep
  it out of the Electron bundle path or verify tree-shaking — `pnpm build`
  (electron-vite) must not break.
- T-107 and T-109 later extend the Tauri side (edit-role local handling,
  drag-drop) — keep the bridge's channel-interception point one obvious
  switch, and note in Log where they should hook.
