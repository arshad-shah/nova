## Goal
`verql-appdata` opens `app.db` with rusqlite using the exact v1 schema and
forward-only `PRAGMA user_version` migrations (v1→v3), WAL + foreign_keys,
corrupt-file quarantine, and serves all 15 `appdata:*` channels with
identical payload shapes — so a v1 `app.db` opens as-is and a v2-created one
is readable by v1.

## Acceptance criteria
- [ ] 1. Migrations are a byte-for-byte port of `MIGRATIONS` in
      `appdata/store.ts`: v1 creates `conversations` (7 cols) +
      `idx_conversations_updated_at`, `messages` (7 cols, FK
      `ON DELETE CASCADE`) + `idx_messages_conversation`, `saved_queries`
      (6 cols) + `idx_saved_queries_updated_at`, `meta`; v2 creates
      `query_history` (9 cols) + `idx_query_history_executed_at`; v3 creates
      `open_tabs` (9 cols incl. `auto_commit INTEGER NOT NULL DEFAULT 1`) +
      `idx_open_tabs_position`. Each migration runs in a transaction that
      also bumps `user_version`. A real v1 `app.db` fixture (all 3 versions)
      opens without schema changes; a fresh DB reaches `user_version = 3`.
- [ ] 2. Open behavior: `journal_mode = WAL` and `foreign_keys = ON` on every
      open; an unopenable/corrupt file is renamed to
      `<path>.corrupt-<timestamp>` and a fresh store created (never a boot
      crash-loop); in-memory path (tests) propagates the error instead.
- [ ] 3. Conversations parity: `listConversations` returns conversations
      newest-updated-first with messages ordered by `seq`, `extra` JSON
      unpacked into optional `toolCalls`/`toolCallId`/`isError` (absent keys
      omitted, not null); `upsertConversation` replaces the message set
      wholesale inside one transaction and upserts stats;
      `deleteConversation` cascades messages and clears
      `activeConversationId` if it pointed at the deleted id;
      `importConversations` is a no-op returning 0 when the table is
      non-empty. `stats` defaults to zeros when absent.
- [ ] 4. Saved-queries parity: list newest-updated-first; upsert preserves
      `created_at` on conflict; optional `connectionType` omitted when NULL.
- [ ] 5. Query-history parity: `listQueryHistory(limit=500)` newest-first;
      optional fields (`connectionId`, `connectionType`, `durationMs`,
      `rowCount`, `error`) omitted when NULL — note `durationMs`/`rowCount`
      use `!= null` (0 survives) while string fields use truthiness (empty
      string dropped), exactly as v1; `addQueryHistory` inserts and prunes to
      newest `max(1, floor(maxItems))` in one transaction (maxItems=0 must
      not wipe the table); delete/clear ported.
- [ ] 6. Open-tabs parity: `listOpenTabs` ordered by `position`, `autoCommit`
      from `auto_commit != 0`, `savedQueryId` omitted when NULL, `activeId`
      from meta key `activeTabId`; `applyOpenTabOps` applies
      upsert/delete/set-active ops in one transaction with the exact upsert
      column mapping (position from the op, not the tab).
- [ ] 7. All 15 channels registered and passing contract round-trip fixtures:
      conversations list/upsert/delete/set-active/import (import returns
      `{ imported: n }`), saved-queries list/upsert/delete/import,
      query-history list/add/delete/clear, open-tabs list/apply.
- [ ] 8. rusqlite calls run on `spawn_blocking` (or a dedicated thread) —
      no async executor thread ever blocks on SQLite I/O (clippy +
      tokio-blocking lint clean).
- [ ] 9. Cross-stack fixture test: a golden `app.db` produced by v1 with
      known rows yields identical `appdata:*` list responses from the Rust
      side (field-for-field).

## Notes
- The `sql` column name in `open_tabs`/`saved_queries` is an opaque buffer
  for any driver's language (see the v3 migration comment) — never parse it.
- Timestamps are integer epoch millis end-to-end; do not convert to SQLite
  datetime.
- Never reorder or edit an existing migration entry — append only. v1 and v2
  share the file during the strangler period; schema divergence bricks
  downgrade.
- Coordination: dispatch-table lines in
  `src-tauri/crates/verql-ipc/src/dispatch.rs` (shared file, 15 match arms).
  T-209 (migrate-v1) copies/opens the same file format — it reads this
  crate's open path; keep `open()` reusable with an explicit path.
