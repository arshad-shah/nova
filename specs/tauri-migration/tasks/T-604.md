## Goal
Windows packaging lands per amended ADR-0008: an NSIS `.exe` as the
guaranteed artifact, and the Store path via the ladder — (a) **EXE/MSI-
linked Store listing** (the officially documented path) primary,
(b) third-party MSIX (`@choochmeque/tauri-windows-bundle`) secondary,
(c) defer-Store tertiary — walked per T-008's outcome **with explicit
human escalation below rung (a)**, never a silent downgrade.

## Acceptance criteria
- [ ] 1. `cargo tauri build` on Windows emits an NSIS `.exe` installer with
      identifier `com.arshadshah.verql`, product name Verql, brand icon
      (build/icon.ico lineage); installs and launches on a real Windows
      machine (frameless window + app-drawn MenuBar + WCO titlebar behavior
      from Phase 1 verified in the smoke).
- [ ] 2. Rung (a) — EXE/MSI-linked Store listing — per T-008's recorded
      outcome: the installer meets the documented Store requirements —
      **code-signed** (the signing line is load-bearing here; v1's appx was
      Store-signed), silent-install flags, and the **offline WebView2
      installer** (`offlineInstaller` bundler mode) — and the Store listing
      is updated/converted so existing Store users receive v2.
- [ ] 3. Rung (b), only if (a) fails: MSIX via
      `@choochmeque/tauri-windows-bundle` over the Tauri build (config
      under packaging/msix/) carrying the **existing v1 Store identity
      verbatim** — identityName `Arshadshah.verql`, publisher
      `CN=2ABEC305-C7D9-4693-92FC-165FCE8EEA94`, publisherDisplayName
      `Arshad shah`, applicationId `Verql`, backgroundColor `#0B0F16`,
      languages `en-US` (package.json#build.appx) — passing WACK / Partner
      Center validation (watch the WACK S-mode failure, tauri#14935).
      Rung (c) is Store submission deferred at cutover, NSIS direct
      distribution. **Each rung's failure evidence is recorded in the Log,
      and moving below rung (a) is escalated to the human owner as a
      product decision — the task cannot be marked done below rung (a)
      without a human sign-off entry in the Log** (ADR-0008 §1).
- [ ] 4. Whatever rung lands, ADR-0008 is amended in the same change to state
      the shipped Windows strategy as `accepted` reality, and T-609's
      cutover checklist input reflects it.
- [ ] 5. CI job builds the NSIS artifact (and MSIX when applicable) on the
      integration branch; job green; artifact sizes recorded for T-606.
- [ ] 6. Platform honesty: the report states which Windows version/hardware
      actually ran the install smoke; nothing is claimed unexercised.

## Notes
- T-008's spike report is the entry point — do not re-derive the MSIX
  landscape from scratch; amend, don't repeat.
- The Store identity block is an existing published-app identity: getting it
  wrong orphans the Store listing. On rung (b), copy the strings from
  package.json#build.appx byte-for-byte; never regenerate GUIDs.
- v1 shipped `appx` via electron-builder with Store signing handled by the
  Store; rung (a) requires the developer's own code signing of the
  EXE/MSI, and local MSIX test-signing needs a self-signed cert — document
  the procedures used (packaging/msix/ for rung b) so the human can
  reproduce them.
- `src-tauri/tauri.conf.json` shared with T-602/T-603 (serialized by design).
