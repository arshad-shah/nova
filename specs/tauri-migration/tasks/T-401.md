## Goal
Seven contribution registries exist as Rust traits + default impls in
`verql-core::registries`, with the exact v1 SDK resolution semantics, so
contribution crates (verql-formats, verql-themes, drivers) register into the
same conceptual surfaces the JS plugins used. Descriptor data stays
serializable (crosses the IPC boundary for `export:formats-list` etc.);
behavior lives in trait objects.

## Acceptance criteria
- [ ] 1. `ExporterRegistry`: `register(id, exporter)` errors on duplicate id
      ("Exporter '<id>' is already registered" semantics); `resolve(format,
      connection_type)` returns the **first registered** exporter (insertion
      order) whose `format` matches and whose `applies_to_types` is absent or
      contains the type; `list(connection_type?)` filters identically.
      Descriptor fields carried: `format`, `extension`, `display_name`,
      `applies_to_types?`, `supports_schema?` (drives the renderer's
      "include schema" toggle — not hardcoded to sql).
- [ ] 2. `ImporterRegistry`: duplicate-id error; `find_by_extension(ext,
      connection_type?)` lowercases and strips a leading dot, matches
      `extensions` case-insensitively, and applies the `applies_to_types`
      filter **only when** the importer declares one. Descriptor carries
      `driver_executes` (SQL importers run statements themselves; the IPC
      layer must not follow with a bulk insert).
- [ ] 3. `FormatterRegistry.resolve(language, connection_type)` implements the
      two-pass precedence exactly: pass 1 returns a formatter with matching
      `language` whose `applies_to_types` contains the type; pass 2 returns a
      matching-language formatter with **no** `applies_to_types`; never
      crosses languages (a sql fallback can never format a json editor).
      Unit test pins conn-specific-beats-generic and the no-cross-language rule.
- [ ] 4. `TypeMapperRegistry`: `register(from, to, table, fallback?)` errors on
      duplicate (from,to); `resolve(from, to, source)` returns identity
      non-lossy when `from == to`, else looks up `source.to_lowercase().trim()`
      in the table, then the fallback fn, else None. `TypeMapping { source,
      target, lossy, note? }` shape preserved.
- [ ] 5. `CommandRegistry`: duplicate-id registration errors; `execute` on an
      unknown id errors ("Command '<id>' not found"); supports the optional
      wrapper hook v1 used for error-budget wrapping.
- [ ] 6. `CompletionRegistry`: one provider per plugin/crate name, silent
      last-write-wins per name (v1 `Map.set`), `get_completions(plugin, conn,
      ctx)` returns `[]` for an unknown provider.
- [ ] 7. `DragDropRegistry`: `register` requires a non-empty id and silently
      replaces a same-id provider (v1 semantics — no duplicate error);
      `resolve_by_extension` lowercases + strips leading dot.
- [ ] 8. All registration handles are RAII/dispose-style (dropping the guard
      unregisters), mirroring v1 `Disposable`, so future dynamic contributors
      (ADR-0003 WASM SDK) can tear down cleanly.
- [ ] 9. Registration order is deterministic and documented: bundled crates
      register in a fixed boot order equivalent to v1's bundled activation
      order (drivers before core-formats' generic fallbacks is NOT required —
      formatter precedence is by `applies_to_types`, but exporter `resolve`
      IS order-sensitive for same-format registrations; a test pins that a
      dialect `sql` exporter shadows nothing it shouldn't).
- [ ] 10. `cargo test -p verql-core` covers every rule above, including the
      exporter same-format multi-registration case (each SQL dialect registers
      `format: "sql"` with distinct ids; `resolve('sql', 'postgresql')` picks
      the postgres one, `resolve('csv', <any>)` picks the neutral CSV).

## Notes
- v1 namespaces exporter/importer/formatter ids as `<pluginName>:<id>` at the
  plugin-host layer (plugin-host.ts `verifyContributions`) — resolution never
  uses the id, only `format`/`language` + `applies_to_types`. Keep ids for
  uniqueness/diagnostics only.
- Descriptors were made declarative (`applies_to_types: string[]`, not
  predicates) in v1 specifically to cross a process boundary — keep them
  serde-serializable structs; only `execute`/`parse`/`format` are trait fns.
- ToolRegistry (last-wins, different semantics) is deliberately NOT here — it
  is T-501 in verql-tools. ThemeRegistry is T-403 in verql-themes.
- Coordination: T-402/T-403 and the Phase-3 driver crates consume these traits;
  land this before reshaping any signature they depend on.
