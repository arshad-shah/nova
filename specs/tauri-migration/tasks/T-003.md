## Goal
The `v2-tauri` integration branch exists (cut from `main`), a Rust CI workflow
runs the standing rust gate on it, and the burndown/gate-report scaffolding is
confirmed in place — so every later merge candidate has a base to rebase onto
and a gate to pass. `main` and its existing CI stay untouched (non-goal:
"v1 stays shippable").

## Acceptance criteria
- [ ] 1. Branch `v2-tauri` exists, created from current `main`, pushed to the
      remote. All migration work merges here per `worktree-protocol.md`.
- [ ] 2. A new workflow `.github/workflows/rust-ci.yml` runs on push/PR to
      `v2-tauri` only, executing the standing rust gate from
      `orchestration/verification.md`: `cargo fmt --check`,
      `cargo clippy --workspace --all-targets -- -D warnings`,
      `cargo test --workspace` — all with
      `--manifest-path src-tauri/Cargo.toml` (or `working-directory:
      src-tauri`), and **skipping gracefully** (neutral, not red) while
      `src-tauri/` does not yet exist (it lands in T-101).
- [ ] 3. The workflow follows the repo's existing CI conventions (see
      `ci.yml`): actions pinned by commit SHA, `permissions: contents:
      read`, a concurrency group, and job timeouts.
- [ ] 4. The existing `ci.yml` is not modified; the pnpm suites
      (typecheck/unit) still run on `v2-tauri` via its existing triggers or
      the new workflow — state which in the Log, and show both green on the
      branch.
- [ ] 5. Confirmed present on `v2-tauri` (created by earlier spec work — do
      not duplicate): `specs/tauri-migration/tasks/channel-burndown.md`
      placeholder and `specs/tauri-migration/tasks/gate-reports/README.md`.

## Notes
- `ci.yml` triggers on `[main, develop]` only — it will NOT run on
  `v2-tauri` pushes. Either extend rust-ci.yml with the pnpm jobs
  (typecheck: `pnpm exec tsc -b --noEmit`; unit: `pnpm exec vitest run
  --project unit` after `pnpm rebuild better-sqlite3`) or accept PR-based
  coverage — criterion 4 forces the choice to be recorded.
- Existence-check pattern for the graceful skip: a first step tests for
  `src-tauri/Cargo.toml` and gates later steps on its output.
- T-103 later adds the contract drift check to CI; keep this workflow's
  job structure amenable (named jobs, not one mega-script).
