## Goal
The `verql-core` foundation modules every Phase-2 crate builds on exist: an
app-data-directory resolver (the v2 equivalent of `app.getPath('userData')`,
resolved via Tauri's path API and overridable for tests), an atomic file
writer with the exact semantics of `src/main/lib/atomic-write.ts`, the
workspace error base (`thiserror` types serializing to the `IpcError
{ message, code?, details? }` wire shape from 04-ipc), and a Rust mirror of
`AppSettings` (all 10 categories in `shared/settings.ts`) with
`default_settings()` and `merge_with_defaults()` ported behavior-identical.

## Acceptance criteria
- [ ] 1. `atomic_write(path, contents, mode: Option<u32>)` writes to a sibling
      temp file named `.<basename>.<pid>.<ts>.tmp`, then renames onto the final
      path; on any error the temp file is removed and the error propagates;
      the parent directory is created if missing; `mode` (e.g. `0o600`) is
      applied to the temp file before rename (no-op on Windows). Unit tests
      cover: crash-safety (old file intact after simulated write failure),
      mode application, and missing-parent creation.
- [ ] 2. The `AppSettings` mirror covers every category in `shared/settings.ts`
      (`general`, `appearance`, `editor`, `dataDisplay`, `ai`, `mcp`,
      `onboarding`, `keybindings`, `plugins`, `disabledPlugins`,
      `pluginGrants`) with `#[serde(rename_all = "camelCase")]` and
      omitted-key handling matching v1 `undefined` semantics.
- [ ] 3. `merge_with_defaults` replicates `shared/settings.ts` exactly:
      object categories are shallow-merged over defaults per-key;
      `keybindings`/`plugins`/`disabledPlugins`/`pluginGrants` are replaced
      wholesale when present; the legacy-default `appearance.accentColor`
      values are cleared (port `LEGACY_DEFAULT_ACCENTS`). A round-trip test
      deserializes a fixture v1 `config.json` `settings` blob and matches a
      golden merged output produced from the TS implementation.
- [ ] 4. `default_settings()` equals `defaultSettings` from `shared/settings.ts`
      field-for-field (pinned by a JSON snapshot test against the TS values,
      e.g. `general.queryTimeout = 30`, `general.maxHistoryItems = 200`).
- [ ] 5. Error base: a core `CoreError` and the `IpcError` serialization exist;
      serializing any error yields `{ message: string }` plus optional
      `code`/`details` (`skip_serializing_if = "Option::is_none"`).
- [ ] 6. Paths module exposes the app-data dir + well-known file paths
      (`config.json`, `app.db`, plugins dir) behind a trait/struct injectable
      in tests (no direct `tauri::AppHandle` dependency in consumer crates).
- [ ] 7. `cargo clippy --workspace --all-targets -- -D warnings` passes; no
      `unwrap()`/`expect()` on paths reachable from IPC.

## Notes
- The v1 atomic writer's docstring is the spec: rename is the atomicity
  mechanism; a half-written temp file must never become the real file.
- `mergeWithDefaults` treats a *present-but-partial* category as "merge over
  defaults", not replace — losing that nuance silently drops user settings on
  first v2 launch. The four replace-wholesale keys are listed in criterion 3.
- Coordination: this task creates `verql-core` modules other Phase-2 tasks
  extend (`activity/` is T-206, `attention.rs` is T-207). Keep `lib.rs`
  module declarations minimal so their additions are one-line and
  conflict-free. Adding the crate to `src-tauri/Cargo.toml` workspace
  `members` touches a line shared with every crate-creating task — rebase
  carefully.
- The AppSettings mirror participates in the contract drift check from T-103;
  if the check flags this crate, fix here, never in `shared/`.
