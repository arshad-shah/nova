## Goal
tauri-bundler produces a working Linux AppImage matching v1's distribution
target, launchable on a clean mainstream distro, wired into CI, with its
sha256 feeding the Homebrew formula (v1 ships a Linux formula too).

## Acceptance criteria
- [ ] 1. `cargo tauri build` on Linux emits an AppImage with identifier
      `com.arshadshah.verql`, product name Verql, and the brand icon
      (build/icon.png lineage); artifact name aligned with the naming scheme
      T-602 pins (lowercase `verql-<version>-<arch>` compatibility for the
      formula URLs, or templates updated in the same change).
- [ ] 2. The AppImage launches on a clean distro without a WebKitGTK dev
      setup: runtime deps (webkit2gtk, libappindicator, etc.) are bundled or
      documented as required system packages exactly as tauri-bundler
      produces them; the boot is verified on at least one distro and the
      distro/version is recorded honestly.
- [ ] 3. Launched app passes a smoke script: window opens frameless with the
      app-drawn MenuBar (Linux shell behavior from T-105/T-106), connects to
      a seeded SQLite file, runs a query.
- [ ] 4. CI job builds the AppImage on the integration branch (workflow
      committed; artifact uploaded); job green.
- [ ] 5. sha256 of the AppImage feeds the render-homebrew pipeline
      (`--sha-appimage`) — a locally rendered Formula/verql.rb references the
      real artifact name (coordinated with T-602).
- [ ] 6. Artifact size recorded and handed to T-606 (v1 AppImage size is in
      the T-004 baseline; the footprint win must be demonstrable).

## Verify
```bash
cd src-tauri && cargo tauri build   # on Linux
ls -lh src-tauri/target/release/bundle/appimage/
chmod +x src-tauri/target/release/bundle/appimage/*.AppImage
./src-tauri/target/release/bundle/appimage/*.AppImage &   # smoke: boots to window
sha256sum src-tauri/target/release/bundle/appimage/*.AppImage
```

## Notes
- AppImage + WebKitGTK has known runtime-dependency sharp edges (this is why
  T-002/T-009 spiked WebView compat) — read their Logs before debugging a
  blank window from scratch.
- No snap/apt channels: they remain planned updater ids (ADR-0008); do not
  add targets beyond AppImage.
- The v1 AppImage was x64-only (electron-builder default); decide arm64
  Linux deliberately and record the decision in the Log — parity does not
  require it.
- `src-tauri/tauri.conf.json` is shared with T-602/T-604 — packaging tasks
  serialize on it by design; keep Linux-specific config in the per-platform
  section to minimize the conflict surface.
